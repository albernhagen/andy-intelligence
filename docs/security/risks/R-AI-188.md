# R-AI-188

**Risk:** Verification run (AI-188: M6.7). (1) A deployed page could steer the verify agent into passing a ticket that doesn't work, which moves it to Done unverified. (2) The agent could reach a host other than the deployment, or write to prod. (3) A wrong merge-commit match could verify a ticket against a deploy that doesn't contain it, or skip one that does.

**Mitigation / next step:** (1) The procedure treats all app content as data and fails a criterion that tries to steer it; the verdict must follow from its parts and name only the task's tickets; passing needs evidence from this run; Andy sees every verdict as a comment. (2) No shell: the profile allows only Read, Glob, Grep and `WebFetch(domain:<host>)`, the host is checked before the agent starts, and WebFetch sends only `GET`. (3) The merge commit comes from the signed `pull_request` webhook, only for merged PRs; containment is GitHub's compare; a ticket without one waits for the 2-hour Needs-you check. Detail: [`verification.md`](../verification.md).
