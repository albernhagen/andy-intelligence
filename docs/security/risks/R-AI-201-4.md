# R-AI-201-4

**Risk:** AI-201: M6.16: Project environment module, with `promote_source_repository` set on prod (`dev-and-prod`), gives prod's Cloud Run service agent read on the dev registry repo so promote ships the verified digest, and (AI-390: Promote in dev-and-prod: prod deployer reads the dev registry) prod's main deployer read on that repo so `release.yml`'s release check can find the digest before traffic moves. It is the one cross-environment grant: an image pushed to the dev repo by the dev main deployer can be deployed to prod by the prod main deployer.

**Mitigation / next step:** Read-only, on one repo, for the service agent and prod's main deployer only; no runtime or preview identity gets cross-project access, and the deployer can't write or delete there. The deployer federates only from `deploy.yml` and `release.yml` on `refs/heads/main` (R-AI-201), so reading dev images needs a merged workflow change; dev images are this repo's own builds, not secrets. Only the dev main deployer (main-only, R-AI-201) can write that repo, and promote passes a digest from a succeeded, verified dev deployment (ADR-0114), never a tag, so a later push can't change what is promoted. Off unless set.
