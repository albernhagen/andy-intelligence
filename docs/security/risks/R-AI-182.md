# R-AI-182

**Risk:** The verify agent (procedure `platform/procedures/verify.md`, AI-182: M6.6) reads what a deployed app returns: pages, responses, console output, test logs. Anyone who can put content in the app (a user of a managed project, a bad dependency) can try prompt injection: pass a broken ticket, leak a value into the verdict, or make the agent change data in prod.

**Mitigation / next step:** The procedure treats all of it as data; text that tries to steer the agent fails the criterion and is quoted for Andy. No write tools and no credentials; on `prod` only `GET`, `HEAD` and `OPTIONS`; stay on the deployed host; secrets redacted from evidence. `VerifyVerdict` refuses a pass without evidence and verdicts that contradict their parts. Until then these rest on the agent's judgment, including the project tests it runs (repo code): AI-188: M6.7: Verification run must enforce the tool list, the network limit (prod read-only), no credentials or env secrets in the sandbox, and the 20-minute cap before it turns Verifying on.
