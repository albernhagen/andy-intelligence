# R5

**Risk:** A PR runs its own workflow files and composite actions, so it can weaken its own reviews (edit a caller workflow, `platform/actions/agent-review-*` or `scripts/review-gate.mjs`), or forge its own findings (ADR-0097; entry point in [`review-pipeline.md`](../review-pipeline.md)).

**Mitigation / next step:** This repo: procedure, schema and threat model come from the base branch; Andy merges every change to CI, review and baseline paths (ADR-0120); build agents' patches can't touch `.github/`, `platform/actions/` or `scripts/review-*.mjs` (ADR-0063). Managed repos (ADR-0038): actions, scripts and procedures come from a pinned andy-intelligence commit; a PR there can only edit its caller file, which `check` reports. Ruleset/CODEOWNERS here later. Lockfiles are left out of the review agents' diff (ADR-0046); `lockfile-sources` fails CI on any locked package not from the npm registry with an integrity hash. `sandbox-self-test` (AI-63) runs the PR's code on a runner with passwordless sudo: `contents: read`, no `id-token`, `persist-credentials: false`, a stub for the model and only fake credentials. The Actions runtime token (artifacts, cache) stays reachable to that code. Its skip gate and test bed come from the PR, so it catches accidents only; Andy's review of those paths is the control. Forged findings only feed config proposals, which change nothing until Andy accepts one.
