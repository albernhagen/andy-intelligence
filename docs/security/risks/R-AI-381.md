# R-AI-381

**Risk:** The setup path shows a step done that isn't (AI-381): a hand mark stands where the App can't read the setting, so a mistaken or false mark can hide a missing reviewer token, environment branch rule or Actions setting. A bug could also show a repo name from storage inside a command Andy copies into his terminal.

**Mitigation / next step:** Only the owner marks (`change_project_settings`); each mark stores who and when and shows as "Marked by hand" with Clear mark. A mark never overrides a live "not yet"; it counts only where the App can't read the result or the read failed. The proving refine (step 10) is read live from the project's agent tasks, so a missing agent token still shows there ("Check the model credential" fails). Repo names in commands are the code host's spelling of a repo registered through `RepoName` (owner/name characters only), so they can't carry shell syntax. Reads use the App's existing permissions only (no new ones), GET inside the repo, capped and cached; no secret or token value is read.
