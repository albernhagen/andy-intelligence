# R-AI-409

**Risk:** The baseline CLI runs with Andy's admin `gh` login (rulesets, security settings, pushes to every managed repo) and, since AI-409, comes from GitHub through `npx -y github:albernhagen/andy-intelligence#<tag>` rather than a checkout he has read. Code that reaches the tag, or a compromise of the repo or of how npx fetches it, runs with that login.

**Mitigation / next step:** Every printed command and runbook pins the CLI to a release tag (`BASELINE_CLI` in `platform/baseline/files.mjs` and `packages/domain/src/onboarding.ts`, kept equal by a test), never unpinned `main`, and `--ref` defaults to that same tag (never "the newest tag"), so code and files share one trust anchor; only the runbook steps that change andy-intelligence's own settings right after a merge use `#main`, by Andy's choice. Tags are cut by Andy from `main`, which `protect-main` guards (checks and both reviews, R23). The package ships only the baseline CLI (`files`), has no dependencies and no install-time script that runs (`postinstall` exits when it isn't this repo). It never runs in CI. Next: protect `v*` tags with a tag ruleset so only Andy can create or move them. Area: [`infrastructure.md`](../infrastructure.md).
