# R-AI-373

**Risk:** `GET /api/projects/{id}/brief` and its MCP twin `brief_status` (AI-373; the tool since AI-379 for ADR-0148 parity) are a new entry point that reads repo files through the App, and returns text from `docs/product/discovery.md`, which anyone who can merge to the repo writes. That text could try to inject markup or instructions into the brief form, or polling could multiply code-host calls.

**Mitigation / next step:** owner only, through the same `submit_brief` permission as the write. It returns only discovery's four known Brief answer ids (`idea`, `problem`, `users`, `business`), each one plain line (whitespace collapsed, a leading `#` escaped) cut to 2,000 characters, and never interprets them. The UI puts them in form fields as text, never markdown, and Andy edits them before submitting. Reads go through the existing `CodeHost` port (`getRepo`, `readFile`): at most three calls per read, with each project's answer reused for 60 seconds per instance (`BRIEF_STATUS_CACHE_MS`, at most 200 projects). A repo that can't be read answers 200 with the reason, never a 500 and never "no brief". No agent task's prompt gets this text; `brief_status` hands it to Andy's own Claude session, which already reads `discovery.md` in the repo (`onboard.md`) and treats it as data.
