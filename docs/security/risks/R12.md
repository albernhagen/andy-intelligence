# R12

**Risk:** A stolen MCP refresh token works until its own 30-day limit (Anthropic holds it; local sessions keep it in the keychain). Rotation happens only in a token's last 7 days and never shortens the old one (ADR-0158: Rotate MCP refresh tokens only near expiry), so using a token is no longer a theft signal: the trade for many sessions sharing one sign-in without dropping. Access tokens last 1 h.

**Mitigation / next step:** Fixed 30-day limit (use never extends it); allow-list re-check each refresh; every refused refresh logged with reason and token age; revoke by deleting `oauthGrants` (runbook `mcp-connector.md` §5). A thief can create backlog tickets, answer questions (Andy still merges), step tickets forward, and edit, comment on, re-parent and reorder them (AI-40: changing what an agent builds or what runs next; history records each change); no delete, forced move or release. No token-family revocation yet. Revisit when `start`, `set_override` or `promote_release` land.
