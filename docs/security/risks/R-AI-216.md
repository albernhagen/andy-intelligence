# R-AI-216

**Risk:** In the `epic` merge mode (AI-216) the App squash-merges child tickets' PRs into `epic/<KEY>` by day, with no night launch's budget or stop time, and outside the default branch's merge queue. It creates `epic/<KEY>` from `main`'s tip when missing and reuses an existing branch of that name without checking who made it or where its tip came from, so commits pushed there by hand reach the epic PR. Two child PRs judged on the same epic tip can both merge and break the branch together.

**Mitigation / next step:** Same gate as night merges (every check and both reviews on the head, protected paths, required checks and CODEOWNERS from the default branch); target from stored tickets and runs only, never PR text; once per child ticket; an epic with more than 50 open or Done child tickets neither builds on nor merges into its branch. Nothing reaches `main` without Andy: the epic PR's head is no agent branch, so the gate never merges it, and its own checks and both reviews run on the whole branch. Next: record the branch's starting sha and refuse a reused branch whose history the App didn't write. Area: [`night-runs.md`](../night-runs.md).
