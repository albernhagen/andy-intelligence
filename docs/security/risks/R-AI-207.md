# R-AI-207

**Risk:** AI-207: M6.18: PR previews. A `cloud-run` project's `preview.yml` runs on `pull_request` and executes the PR's own code, its workflow file and Dockerfile included, holding the `<service>-pr-deploy` identity and a `GITHUB_TOKEN` with `pull-requests: write`. Anyone who can push a branch to the managed repo (Andy, build agents through the GitHub App) can therefore: deploy any image as any revision of `<service>-preview`, remove or move other PRs' `pr-<n>` tags (beating the 10-tag cap or hiding another preview), set the preview's per-revision max instances up to Cloud Run's limits (spend), and comment on or edit PRs. In `prod-only` the preview service sits in the prod GCP project. The 10-tag cap counts tags, and `preview_max_instances` caps each revision, so up to 10 tagged revisions could each run that many instances.

**Mitigation / next step:** Forks and Dependabot PRs get no job (job-level `if` on the head repo and author; GitHub gives fork runs no OIDC token either), and the identity federates only on `event_name == pull_request` of one repo by name and ID, so `pull_request_target` and other repos are refused (R-AI-201-2). The identity reaches only the preview service, its own registry repo and `<service>-pr-run`, which has logs and traces only: no prod data, no main service, no IAM, no other project; Cloud Run IAM stays on, and PR code can't turn it off. Revisions are no-traffic; the service's own URL keeps serving what Terraform set. The action keeps at most 10 `pr-<n>` tags (oldest generation removed first, before and after each deploy) and removes the PR's tag on close; untagged revisions scale to zero and cost nothing. Spend: Terraform's per-revision instance cap (1 by default, at most 3), drift on the next plan, the project budget, kill switch and usage alerts. PR number validated before it names a tag; inputs reach shell only through `env`; actions pinned by SHA. Next: a service-level instance cap on `<service>-preview` in `project-env`, so all previews together share `preview_max_instances` (proposed as a follow-up ticket).
