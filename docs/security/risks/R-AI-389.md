# R-AI-389

**Risk:** AI-389: M6.23: Deploys and promotes tag the image prod runs. In `dev-and-prod`, promote tags the digest it ships `release-<hex>` in the dev registry repo, so prod's main deployer gets `artifactregistry.writer` on that one repo (no tag-only predefined role exists), replacing the read AI-390: Promote in dev-and-prod: prod deployer reads the dev registry gave it to check the digest. Writer also lets it push images and move or delete tags there.

**Mitigation / next step:** One repo, prod's main deployer only, which federates only from `deploy.yml` and `release.yml` on `main` (R-AI-201) and already controls prod, the higher-trust environment. Dev deploys only the digest its own build pushed and promote ships a digest, never a tag, so a pushed image or a moved tag changes neither environment. A deleted `release-*` tag only lets cleanup delete that image later. Off unless `promote_source_repository` is set. A custom tag-only role would narrow it if needed.
