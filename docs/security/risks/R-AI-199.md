# R-AI-199

**Risk:** Promote and rollback (AI-199: M6.12, ADR-0160). A new entry point changes what serves prod: the owner's routes and MCP tools start a project's `release.yml` with the GitHub App token. A stolen sign-in or MCP grant, or a coordinator session misusing Andy's grant, could ship an older or unverified image to prod or roll prod back; a flood could keep prod churning.

**Mitigation / next step:** Owner-only (`requireCan`, allow-list, project access); only a digest or revision from a succeeded deployment of that project and environment, and never for `deployKind` `none` or a `prod-only` promote; one request per project per minute, enforced in a transaction across instances; every request recorded with its actor, target, run and outcome, and logged; the workflow's start report must match its request or is refused (`422`); a queued check marks cancelled or unreported runs. No cloud credential in the API; the App is never widened. Next: push cancelled requests to Needs-you (follow-up). Detail: `release-requests.md`.
