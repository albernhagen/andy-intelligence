# R-AI-190

**Risk:** Release reports and the release workflow (AI-190: M6.11). The deployment callback now also accepts `release.yml` on `main`, so a second workflow can write promote and rollback records; anyone who can run `release.yml` (repo write access) can move prod traffic to any ready revision of the service or ship any image digest in the registry. A release run may finish any started promote or rollback of its project.

**Mitigation / next step:** Exact `workflow_ref` (`deploy.yml` or `release.yml`, `@refs/heads/main` only); `deploy.yml` reports only kind `deploy`, `release.yml` only `promote` or `rollback`; a release record takes its commit from a succeeded deployment of the same digest, and an unknown digest records nothing (`422`); `release.yml` stops a promote on that `422` before traffic moves. The workflow refuses other refs, checks inputs and that the revision or digest exists before traffic moves, and takes inputs through `env` only. Same body cap and rate cap as R-AI-180. Detail: `deployments.md`.
