# R-AI-155

**Risk:** Planned, not built (ADR-0116: Dependency agent). The control plane merges Dependabot PRs into `main` on its own with the GitHub App token, in every registered repo. (1) A hijacked npm patch or minor, or a malicious Action release at its correct tag SHA, that passes every check now merges and deploys without Andy. (2) Andy grants the App `workflows` now (2026-11-26), which removes GitHub's own block on the App changing workflows on every installed repo, so a stolen App key or a control-plane bug could rewrite CI there (R19, R-AI-113). (3) A forged commit or label on a Dependabot branch could make a non-Dependabot change look like a bump.

**Mitigation / next step:** (1) 7-day cooldown; dependency review, CodeQL and Trivy; every check on the head must pass, not only required ones; no new install scripts; Actions bumps only at a SHA that is the tag's commit in the action's own repo, only actions already in use, never auth, deploy, review or executor actions; deploys go through the smoke-tested safe deploy, dev first for `dev-and-prod`; a red `main` holds every later merge; every bot merge is in the digest; at most 10 a day per project. (2) `mergeVerdict` refuses every kept path until AI-164 adds the verified-pin exception, so Actions bumps stay Andy's click; CI and agent tokens stay scoped to contents and pull requests; Andy can revoke the grant; file and baseline proposals keep refusing workflows. (3) Classified from GitHub facts on the exact merged head, never PR text; any commit not by `dependabot[bot]` sends the PR to Andy; labels are display only. Built in AI-157, AI-163, AI-164.
