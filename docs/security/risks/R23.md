# R23

**Risk:** A coordinator session merges every PR that passes checks and both reviews to `main` without Andy reading it (ADR-0120). It reads ticket text, PR text, review comments and worker reports, all untrusted; injected text or a weakened reviewer could pass a harmful PR; docs-only PRs reach it with no agent verdict.

**Mitigation / next step:** Mechanical: `protect-main` blocks a merge until every required check passes on the head, both review agents among them, squash only; CODEOWNERS only requests Andy's review. Not in the ruleset: the sync condition (`merge-queue.mjs` checks it when used), and docs-only PRs, which the agents skip (ADR-0030): the coordinator reads the diff itself. Procedural: ADR-0120's conditions in `platform/procedures/coordinate.md` §7 (no finding open, one at a time, `main` green after each; never what judges a PR, its own rules, or what needs Andy), applied by hand; review procedures come from the base branch (R5); each merge has a release note Andy reads (AI-159). ADR-0124 (proposed): sessions merge via MCP `merge_pr` (project merge mode, App token); GitHub requires Andy's approval on kept paths.
