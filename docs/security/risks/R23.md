# R23

**Risk:** A coordinator session merges PRs to `main` without Andy reading them. It reads ticket text, PR text, review comments and worker reports, all untrusted; injected text or a weakened reviewer could pass a harmful PR. Sessions still hold Andy's GitHub token, so a session that ignores its procedure could merge directly.

**Mitigation / next step:** Since AI-220 the coordinator merges only through MCP `merge_pr` (ADR-0124): owner only, capped at 30 calls per project per hour, it reads the facts from GitHub (never PR text), applies `mergeVerdict` under the project's or ticket's stricter merge mode, and merges with the App token, squash, pinned to the judged head. The clean rule is code: every required check and both review agents passed on the head, the head contains the latest `main` (read fresh against the base tip, which is re-read before the merge), no open finding or accepted label, ticket in Ready for review, no kept path. Docs-only PRs (agents skip them, ADR-0030) and agent PRs never merge through it. No queue or lock: one call at a time, the fresh up-to-date check and the pinned head keep two merges apart; ordering is AI-110: M5.18: Merge queue per repo (GitHub does not require up-to-date branches; AI-284 cancelled). `protect-main` still requires every check and both reviews. Still procedural until sessions get a token without merge rights: not merging with Andy's token (`coordinate.md` §7, runbook `coordinating-sessions.md` §5); GitHub enforcing the kept kinds is AI-217. Review procedures come from the base branch (R5); each merge has a release note Andy reads (AI-159) and a comment on its ticket.
