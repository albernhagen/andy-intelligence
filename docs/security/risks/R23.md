# R23

**Risk:** A coordinator session merges PRs to `main` without Andy reading them, while reading untrusted ticket text, PR text, review comments and worker reports; injected text or a weakened reviewer could pass a harmful PR. Sessions still hold Andy's GitHub token, so one could merge directly.

**Mitigation / next step:** Sessions merge only through MCP `merge_pr` (AI-220, ADR-0124): owner only, 30 calls per project per hour, GitHub facts only, `mergeVerdict` under the merge mode, App token, squash, pinned to the judged head. Clean is code: every check and both reviews passed on the head, head contains the latest `main` (base tip re-read before merging), no open finding or accepted label, the PR's linked ticket in Ready for review, no kept path. Docs-only and agent PRs never merge through it. Calls for one repo run one at a time per instance; across two instances overlapping calls can both merge, so one call at a time stays procedural until AI-110: M5.18: Merge queue per repo. Also procedural: not merging with Andy's token (`coordinate.md` §7, runbook §5); kept kinds enforced by GitHub is AI-217. `protect-main` requires every check and both reviews; review procedures come from the base branch (R5); each merge gets a release note (AI-159) and a ticket comment.
