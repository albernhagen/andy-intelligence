# R23

**Risk:** A coordinator session (Claude desktop, run by Andy) merges low- and medium-risk PRs to `main` without Andy reading them (ADR-0078, ADR-0088). It reads ticket text, PR text, review comments and worker reports, all untrusted; injected text could talk it into calling a high-risk PR medium, or a worker could write a PR that reads as docs-only; docs-only PRs reach it with no agent verdict.

**Mitigation / next step:** Mechanical today: the `protect-main` ruleset blocks a merge until every required check passes on the head, both review agents among them, and allows squash only; CODEOWNERS requests Andy's review on every PR (not a block). Not mechanical: the sync condition (the ruleset does not require up-to-date branches), and review of docs-only PRs, which the agents skip (ADR-0030), so the coordinator reads such a diff itself and records it. Procedural: the classes (ADR-0078, ADR-0084, ADR-0092's high-risk list) in `platform/procedures/coordinate.md` §7 and runbook `coordinating-sessions.md` §5 (size S or M, no finding open, never access, infra, schema, review system or its own rules), applied by hand; every merge recorded in Andy's digest. M1.8b: Gate and auto-merge (AI-34) makes the path and veto rules mechanical for product merges; this row retires when project `AI` turns `autoMerge` on and the coordinator stops merging.
