# R-AI-239

**Risk:** A routing save decides which provider and model run agent tasks. A bad or forged save could send tickets and code to a provider Andy didn't choose, or onto a pay-per-use route that spends money.

**Mitigation / next step:**

- Built (AI-239): saves are owner-only (`change_routing`, the one permission function) behind the sign-in allow-list; agents and the system get 403. Every route must pass `routeProblem` (harness ↔ provider ↔ model); a project config may only narrow global (no provider global turns off, no route global doesn't list, no looser levels). Stale writes are refused (409).
- Built: every save is a ConfigChange (who, when, before and after); a project's are shown in its settings change log, global ones on Settings → Models and over MCP `list_routing_changes` (AI-275). A failed append logs an ERROR with the diff.
- Built (AI-275): an owner-only revert writes the before values back through the normal save (validated, narrowed, logged), refused when a later change touched the same parts or for a project's first save. The revert route and tool name no project, so they check the change's project with `ProjectAccess.canRead` (AI-252; an unreadable one is not found); the global log is owner-only (`change_routing`).
- The narrowing check reads global outside the project write, so a global save in between can leave a stored project config wider than global; AI-238: M9.6 narrows to the current global at run time, so it never widens what runs.
- Live since AI-238: M9.6: Route resolver: each dispatch reads the stored routing, so a save changes which provider and model run agent tasks at once. Defaults: only claude-sub is on; google-sub and openrouter stay off until Andy turns them on, and Jules can't run until M9.10.
- M10: Paid models + spend caps: USD caps before openrouter can spend.
