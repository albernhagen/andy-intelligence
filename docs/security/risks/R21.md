# R21

**Risk:** Agent PRs on managed projects merge to `main` on their own when checks and both review agents pass (ADR-0050). An injected ticket could steer a build into `main` with no human on any path the gate doesn't protect.

**Mitigation / next step:** Built in M1.8: Build + gate. Protected paths (`PROTECTED_GLOBS`, `TOOLING_GLOBS` in `packages/domain/src/gate.ts`, matching ADR-0078's Andy-merges list where a path can express it (stricter than the coordinator's ADR-0092 list until the `autoMerge` trial aligns them), plus CODEOWNERS paths after `*` read from the base branch) never auto-merge; a rename counts under both names and editing CODEOWNERS is itself protected. PR text is not a gate input. Required checks are read live with their reporting app; both review checks must be `success` from the trusted reporter; no branch rules is a veto. Only the gate writes `wouldAutoMerge`; run reports cannot. The `autoMerge` policy is set only by a signed-in user (Project settings, `set_auto_merge`) and cannot override a veto. Merge is by the App token, a bot actor that never deploys this repo, pinned to the assessed head, one attempt per head. Project `AI` stays `autoMerge: none` until the safe deploy path (M2: Self-hosting). Residual: verification output is agent-reported (advisory); the review agents are the only judgement on unprotected paths until M1.17: Agent evals v1, and their spec pass has no acceptance-criteria input on agent PRs yet.
