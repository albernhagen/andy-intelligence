# R-AI-242

**Risk:** Project members (M8: Project members, ADR-0127) add people other than Andy behind the sign-in gate. A missed check would let a member read another project, change settings, or start agent tasks on Andy's quota; a member's ticket text and answers are input to agents with write access to his repos; a removed member could keep MCP or push access.

**Mitigation / next step:**

- Planned, in order: one project-access check with 404 for non-members and a registry test over every route and tool (AI-252: M8.3); roles in `can` (AI-253: M8.4); member sign-in with access re-resolved per request (AI-254: M8.5); viewer and contributor write rules, queuing to Up next owner-only (AI-255: M8.6); cross-project lists filtered (AI-256: M8.7); 60 writes per member per hour (AI-262: M8.8).
- No member can be added before all of these ship (AI-263: M8.9, which also deletes grants and push subscriptions on removal).
- Severity: high until AI-263 ships with the rest in place; no member exists before then.
