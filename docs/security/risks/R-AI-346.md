# R-AI-346

**Risk:** A PR merges with no review of its head. Before AI-346, a review that couldn't run (a bot-started run, quota, outage, no token) passed its check, and every push by the re-sync bot (ADR-0111) produced one. The fix carries a verdict over a re-sync merge, so a faulty carry-forward could pass changes no agent saw.

**Mitigation / next step:** ADR-0140. "Not reviewed" fails the check unless Andy adds the override label (removed on every push). Only skips by design pass: docs-only, draft, Dependabot. A verdict carries forward only when all hold: `github.actor` is the re-sync bot on `synchronize`; the head is a merge whose first parent is the commit the verdict reviewed and whose second parent is on the base branch; that verdict passed (✅, not label-accepted); and the PR's own diff is the same (`git patch-id --verbatim`). Otherwise the check fails until a person pushes. The gate re-reads the previous comment and checks it again. Tests use a bot-authored head, including a merge that sneaks in a change. Agent PRs from the App were never reviewed for the same reason, and now fail closed too; a real review for them is a follow-up. Residual: the previous verdict is read from a `github-actions[bot]` comment, so a same-repo PR workflow that writes a fake ✅ comment could fake it. It could already rewrite the review workflow itself (R2), and changes to `.github/` and the review scripts are Andy's to merge.
