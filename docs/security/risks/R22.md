# R22

**Risk:** Ticket text goes into the executor agent's prompt (M1.6a). Injected text could steer it to read secrets or plant text in its report; from M1.8a the build agent has Bash and its change, plan and summary become a PR. The prompt shows in the Actions log (public here).

**Mitigation / next step:** Profile: no Bash or web tools for refine, plan; secret reads denied; nothing outside the checkout; no project hooks or MCP; prompt marks ticket text as data, escapes `<`; report capped, shown as text; refine's checked result reaches only its ticket and fills only empty fields (ADR-0075), except a split: ≤ 5 children, in Ideas, never auto-refined, so a person must pick each one; otherwise only Andy creates tickets. Build: off until Andy sets `buildEnabled` (recorded); sandbox, scrub; git from a pre-agent `.git`; publish checks paths, flags tooling; Andy or the coordinator merges (ADR-0120). Plans (ADR-0050): owner-only (AI-19), recorded; approved ones go in escaped. Log exposure accepted for `AI`; fix before private projects (M5: Multi-project in parallel). Accepted: mid-build git reads agent-written objects (ADR-0071); Bash can read the read-only job token in `.git/config` (expires with the job; AI-47).
