# R-AI-201-2

**Risk:** AI-201: M6.16: Project environment module's preview deployer, `<service>-pr-deploy`, is usable by any `pull_request` run of the managed repo, and that run executes the PR's own code, workflow file included. Anyone who can push a branch to the repo (Andy, build agents through the GitHub App) can therefore use it: deploy any image to `<service>-preview`, change that service's env, scaling up to Cloud Run's limits (spend) or delete it. In `prod-only` the preview service sits in the prod GCP project.

**Mitigation / next step:** Bound to `event_name == pull_request` in a provider that accepts only the one repo (name and ID); fork PRs never get an OIDC token on a public repo, and `pull_request_target` is a different event. `run.developer`, push and actAs only on the preview service, its own registry repo (so it can't overwrite an image `main` deploys) and its own runtime identity `<service>-pr-run`, which has logs and traces only: no `runtime_project_roles`, so no prod data. actAs on that one identity means a deploy can't switch the preview to the main runtime identity. Spend: Terraform caps it at 1 instance (at most 3) and a change shows as drift on the next plan; the project budget, kill switch and the usage alerts catch a raise. Cloud Run IAM stays on unless `preview_allow_unauthenticated`.
