# R-AI-388

**Risk:** Andy's Merge button (AI-388, ADR-0157) lets the control plane merge the kinds the merge mode keeps for him (kept and high-risk paths, `manual` mode) with the App's identity. Anyone who can send `POST /api/projects/{id}/merges` as Andy can do that: a session or agent driving Andy's signed-in browser, or a stolen Firebase ID token. An approval reused on a head Andy never saw would merge a change he didn't approve. The queue's own sync writes to PR branches with the App's token, and `POST /github/pr-sync` is a new public route.

**Mitigation / next step:** The route is behind the `/api` sign-in (allow-list) and `requireCan`; the MCP grant sessions use can't reach it, and `merge_pr` never waives the mode. The click waives only `ANDYS_MERGE_REASONS`: checks, both reviews, findings, Ready for review and a red `main` still hold the PR. The approval is pinned to the PR's own diff (`diffDigest`, hunk line numbers left out); any new change drops it ("click Merge again"), and a diff the host can't show in full is refused. Caps: 30 merges per project per hour; the sync only through the queue (one per head, 3 per PR, 60 minutes), pinned to the judged head; the settings route answers one value to the repo's own `resync-prs.yml` on `main` only, ≤ 30 reads/minute. Agents' rules forbid acting in Andy's browser beyond their task. An MCP access token gets 401 on the route (tested). `diffDigest` refuses a diff with any patchless entry but a pure rename (binary, huge, mode-only); a mode change on a file that also changes lines is not visible to it. Next: ask for a fresh sign-in (recent `auth_time`) before an approval that waives a kept path (security review on PR #441).
