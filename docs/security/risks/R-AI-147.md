# R-AI-147

**Risk:** PR re-sync (AI-147, ADR-0111) merges `main` into open same-repo PRs with an App repo token on every push to `main`, without a person starting it. A bad change merged into its workflow or script would run with that token (contents and pull requests write on this repo for an hour); a merge could land on a branch a worker is still changing.

**Mitigation / next step:** Token only for `resync-prs.yml` on `refs/heads/main` (`TOKEN_POLICY`, OIDC-checked; no stored secret); changing either needs a PR Andy merges. GitHub makes the merge (update-branch with `expected_head_sha`): clean merges only, never rebase or force. No PR file is checked out and no PR code runs (`git merge-tree` on objects). Skips forks, drafts, `agent/*`, Dependabot and `no-auto-sync`. Caps: 4 runs an hour, 20 PRs a run, 3 merges of `main` per PR a day. Off unless the repo variable `RESYNC_PRS` is `on`. Workers pull with merge before pushing (runbook `coordinating-sessions.md` §6). Detail: `entry-points-and-credentials.md`.
