# Threat model: UI and MCP

Browser sign-in, GitHub setup and MCP. Risks: [risks/](risks/); assets, mitigations: [threat-model.md](threat-model.md). PRs changing this area update this file; the weekly review edits only the main one and risks.

| --------------------------------------------------------------------------------------------------------------------- | ---------------- | ------------------------------------------------------------------- | ------------------------------- |

## Credentials and identities

| Identity / secret                     | Grants                                                                                                                                                                                                                 | Usable from                                        |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| MCP OAuth codes and tokens (ADR-0039) | Code (60 s, single-use, PKCE-bound): one token exchange. Access token (1 h): `/mcp` as Andy. Refresh token (30 days, rotated; a used one works 60 s more, ADR-0105): new access tokens. Allow-list re-checked each use | Whoever holds them: Claude (Anthropic stores them) |

- **Worker (ADR-0082):** `PUT /api/projects/:id/tickets/:id/worker` and MCP `set_worker`, `set_default_worker`, behind the allow-list. They store a fixed-list choice as the signed-in user. Switching to an agent starts a build only under the existing `buildEnabled`, `autoBuild` and run caps. Agent runs can't reach them.
- **Project plans (AI-108):** `…/plan`, `…/plan/decision`, `GET /api/project-plans/waiting`, MCP `*_project_plan`: owner-only (`start_run` to submit until AI-134, `decide_plan`). A capped plan is stored on the project (not via `PATCH`) and creates no ticket; approval makes at most 10 epics, recording each, so retries don't duplicate. Untrusted text.
- **Owner-only rules (AI-19):** one policy, `can(actor, action, project)` in `packages/domain/src/permissions.ts`, decides force move, reopen, cancel, archive, start a run, answer, promote an assumption, accept a held gap, decide a plan, pick the worker, change routing, project settings (deciding or reverting a config change counts as one), clearing a quota idle and submitting a brief; agents and the system get `forbidden` (403). Every `user:<uid>` actor is the owner today (only allow-listed users pass `/api` and `/mcp` auth), so the allow-list is the trust boundary until AI-18: Project members. History stores the Firebase uid, not the email; refusals log the actor and action (`owner-only action refused`); the builds-switch log records the actor. Stored `andy` reads as the owner (no migration).
- **In-flight view (ADR-0080):** `GET /api/projects/:id/in-flight` and MCP `list_in_flight` are read-only, allow-listed and scoped to one project. They return per-ticket run metadata (branch, PR, touches, reserved ADR number); titles are untrusted, rendered as text. The ADR number is parsed as digits from the default branch's index and enters prompts only as a number. `touches` match only a bounded glob subset without regular expressions; anything else counts as overlapping (no ReDoS).
- **Routing layers (AI-282: M9):** `GET /api/projects/:id/tickets/:id/routing` and the `routing` field of MCP `status`: read-only, allow-listed, one ticket; three reads (ticket, epic, routing configs). They return config values and fixed reason strings; the epic key is shown as text.
- **Ranked Ready list (AI-298):** `GET /api/projects/:id/ready` and MCP `list_ready`: one read, allow-listed, one project, at most 100 tickets; reasons render as text.
- **Milestone map, roadmap (AI-148, AI-193):** `…/milestone-map`, `…/roadmap`, `GET /api/roadmap`, MCP `milestone_map`, `roadmap`: read-only, allow-listed. Map: one ticket list, ≤ 50 histories. Roadmap: boards via the read cache, ≤ 50 readable projects (`canRead`). Titles untrusted.
- **Setup checklist (AI-95):** `GET /api/projects/:id/setup` is read-only and allow-listed. Checks the first repo's files with the App token (no new credential): 15 code-host calls per read, cached 5 minutes in the browser. Code-host errors are clipped to 200 characters, shown as text.
- **Config proposals (ADR-0097):** `POST /api/projects/:id/config-proposals/sweep`, `GET /api/config-changes`, `POST /api/config-changes/:id/accept` and `/reject`, the inbox control and MCP `list_config_changes`, `sweep_config_proposals`, `accept_config_change`, `reject_config_change`, allow-listed; deciding is owner-only (the project-settings rule). A sweep writes only pending `ConfigChange`s (one per project a minute per instance; 5 per sweep; 10 pending per project, checked in the write's transaction). Accepting records agreement; nothing applies a change to `AGENTS.md` or a procedure. Review finding titles are untrusted agent text: URLs become "link removed" and every character but letters, digits, spaces and plain punctuation is dropped, so no Markdown, HTML, mention or control character reaches proposed text; the UI shows it as plain text. The findings writer (new entry point) comes with ADR-0097 PR B and its threat-model rows.
- **Routing settings (AI-239):** `GET /api/routing`, `PUT /api/routing`, `PUT /api/projects/:id/routing`, `GET /api/routing/changes`, `POST /api/routing/changes/:id/revert`, MCP `get_routing`, `set_tier_routes`, `set_provider_routing`, `set_step_tier`, `list_routing_changes`, `revert_routing_change`; allow-listed reads (at most 50 projects per view), owner-only writes (`change_routing`). A save is refused (422) unless every route passes `routeProblem` and a project config only narrows global; a stale `ifUpdatedAt` is a 409. Each save is one ConfigChange; a revert (AI-275) goes back through the same save, so it is validated and logged, and is refused (409) when a later change touched the same parts or for a project's first save. Risk: [R-AI-239](risks/R-AI-239.md).
- **Brief and ideation (AI-107, AI-114):** owner-only `…/brief`, `…/ideate`, MCP `submit_brief`, `ideate`; capped. The App commits one file (brief or new `specs/<slug>.md`) on a fresh branch, deleted on failure, never `.github/`, `.claude/` or `..`; Andy merges (5, 10/hour). Questions: one Ideas ticket.
- **Service worker (AI-172):** `/sw.js`, no fetch handler or cache. Untrusted push payloads: only string `title`, `body`, `url` shown; taps open same-origin `url` only, else `/`.
