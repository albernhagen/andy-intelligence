## Credentials and identities

| Identity / secret                     | Grants                                                                                                                                                                                              | Usable from                                                          |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| MCP OAuth codes and tokens (ADR-0039) | Code (60 s, single use, PKCE-bound): one token exchange. Access token (1 h): `/mcp` as Andy. Refresh token (30 days, rotated on use): new access tokens. Re-checked against the allow-list each use | Whoever holds them: Claude (Anthropic stores them for the connector) |

- **Worker (ADR-0082):** `PUT /api/projects/:id/tickets/:id/worker` and MCP `set_worker`, `set_default_worker`, same allow-list. They store a choice from a fixed list, recorded as the signed-in user. Switching to an agent builds only under the existing `buildEnabled`, `autoBuild` and run caps; agent tasks can't reach them.
- **Project plans (AI-108):** `POST /api/projects/:id/plan`, `…/plan/decision`, `GET /api/project-plans/waiting`, MCP `submit_project_plan`, `approve_project_plan`, `reject_project_plan`: owner-only (`start_run` to submit until AI-134, `decide_plan` to decide). A plan is schema-checked and capped (10 milestones), stored on the project, and creates no ticket; approval creates at most 10 epics, recording each (`approving`), so a failed approval resumes without duplicates; one decision per project at a time per instance. Emailed like tickets. Plan text is untrusted. `PATCH /api/projects/:id` can't set the plan.
- **Owner-only rules (AI-19):** one policy, `can(actor, action, project)` in `packages/domain/src/permissions.ts`, decides force move, reopen, cancel, archive, start a run, answer, promote an assumption, accept a held gap, decide a plan, pick the worker, project settings (config-change decisions included) and clearing a quota idle; agents and the system get `forbidden` (403). Every `user:<uid>` is the owner today (only allow-listed users pass `/api` and `/mcp` auth), so the allow-list is the trust boundary until AI-18: Project members. History and the builds-switch log store the Firebase uid, not the email; refusals log actor and action (`owner-only action refused`). Stored `andy` reads as the owner (no migration).
- **In-flight view (ADR-0080):** `GET /api/projects/:id/in-flight` and MCP `list_in_flight` are read-only, behind the same allow-list, and scoped to one project. They return run metadata already shown per ticket (branch, PR, touches, reserved ADR number); titles render as text. The ADR number is parsed as digits from the default branch's index and enters the build prompt only as a number. `touches` match only a bounded glob subset, no regular expressions; anything else counts as overlapping (no ReDoS).
- **Setup checklist (AI-95):** `GET /api/projects/:id/setup` is read-only, behind the same allow-list. It checks files on the project's first repo with the existing App installation token (no new grant): 14 code-host calls per read, cached 5 minutes in the browser. Code-host errors are clipped to 200 characters, rendered as text.
- **Config proposals (ADR-0097):** `POST /api/projects/:id/config-proposals/sweep`, `GET /api/config-changes`, `POST /api/config-changes/:id/accept` and `/reject`, the inbox control and MCP `list_config_changes`, `sweep_config_proposals`, `accept_config_change`, `reject_config_change`, behind the same allow-list; deciding is owner-only (the project-settings rule). A sweep only writes pending `ConfigChange`s (one per project a minute per instance; 5 per sweep; 10 pending per project, checked in the write's transaction). Accepting only records agreement; nothing edits `AGENTS.md` or a procedure. Review finding titles are untrusted agent text: URLs become "link removed" and every character but letters, digits, spaces and plain punctuation is dropped, so no Markdown, HTML, mention or control character reaches proposed text; the UI shows it as plain text. The findings writer (a new entry point) and its rows come with ADR-0097 PR B.
- **Night launch (AI-120, ADR-0049):** `GET`/`POST …/tickets/:id/night`, `…/night/stop`, MCP `night_status`, `launch_night`, `stop_night`: same allow-list; launch and stop owner-only (`start_run`). Refused while a story is open; budget capped (`NIGHT_LIMITS`); reads ≤ 50 stories. MCP launch has no extra gate: decide one before M4.18 dispatches. Question text renders as text.
