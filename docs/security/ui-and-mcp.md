## Credentials and identities

| Identity / secret                     | Grants                                                                                                                                                                                              | Usable from                                                          |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| MCP OAuth codes and tokens (ADR-0039) | Code (60 s, single use, PKCE-bound): one token exchange. Access token (1 h): `/mcp` as Andy. Refresh token (30 days, rotated on use): new access tokens. Re-checked against the allow-list each use | Whoever holds them: Claude (Anthropic stores them for the connector) |

- **Worker (ADR-0082):** `PUT /api/projects/:id/tickets/:id/worker` and MCP `set_worker`, `set_default_worker`, behind the same allow-list as every other route and tool. They store a choice from a fixed list, recorded as the signed-in user. Switching to an agent can start a build only under the existing `buildEnabled`, `autoBuild` and run caps. Agent runs can't reach them.
- **Owner-only rules (AI-19):** one policy, `can(actor, action, project)` in `packages/domain/src/permissions.ts`, decides force move, reopen, cancel, archive, start a run, answer, promote an assumption, accept a held gap, decide a plan, pick the worker, project settings (accepting or rejecting a config change counts as one) and clearing a quota idle; agents and the system get `forbidden` (403). Today every `user:<uid>` actor is the owner, because only allow-listed users get past `/api` and `/mcp` auth: the allow-list stays the trust boundary until AI-18: Project members. History stores the Firebase uid, not the email; refusals log the actor and action (`owner-only action refused`), and the builds-switch log now records the actor instead of the email. Stored `andy` reads as the owner (no migration).
- **In-flight view (ADR-0080):** `GET /api/projects/:id/in-flight` and MCP `list_in_flight` are read-only, behind the same allow-list, and scoped to one project. They return run metadata already visible per ticket (branch, PR, touches, reserved ADR number); ticket titles are untrusted text, rendered as text. The ADR number is parsed as digits from the default branch's index and enters the build prompt only as a number. Ticket and run `touches` are matched only in a bounded safe glob subset without regular expressions; anything else counts as overlapping (no ReDoS).
- **Setup checklist (AI-95):** `GET /api/projects/:id/setup` is read-only, behind the same allow-list. It checks file presence on the project's first repo with the existing App installation token (no new credential or grant): a fixed 15 code-host calls per read, cached 5 minutes in the browser. Code-host error text is clipped to 200 characters and rendered as text.
- **Config proposals (ADR-0097):** `POST /api/projects/:id/config-proposals/sweep`, `GET /api/config-changes`, `POST /api/config-changes/:id/accept` and `/reject`, the inbox control and MCP `list_config_changes`, `sweep_config_proposals`, `accept_config_change`, `reject_config_change`, behind the same allow-list; deciding is owner-only (the project-settings rule). A sweep only writes pending `ConfigChange`s (one per project a minute per instance; 5 per sweep; 10 pending per project, checked in the write's transaction). Accepting records agreement; nothing applies a change to `AGENTS.md` or a procedure. Review finding titles are untrusted agent text: URLs become "link removed" and every character but letters, digits, spaces and plain punctuation is dropped, so no Markdown, HTML, mention or control character reaches proposed text; the UI shows it as plain text. The findings writer (a new entry point) comes with ADR-0097 PR B and its threat-model rows.
