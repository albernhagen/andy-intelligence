## Credentials and identities

| Identity / secret                     | Grants                                                                                                                                                                                              | Usable from                                                          |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| MCP OAuth codes and tokens (ADR-0039) | Code (60 s, single use, PKCE-bound): one token exchange. Access token (1 h): `/mcp` as Andy. Refresh token (30 days, rotated on use): new access tokens. Re-checked against the allow-list each use | Whoever holds them: Claude (Anthropic stores them for the connector) |

- **Worker (ADR-0082):** `PUT /api/projects/:id/tickets/:id/worker` and MCP `set_worker`, `set_default_worker`, behind the allow-list. They store a fixed-list choice, recorded as the signed-in user. Switching to an agent builds only under the existing `buildEnabled`, `autoBuild` and run caps; agent tasks can't reach them.
- **Project plans (AI-108):** `…/plan`, `…/plan/decision`, `GET /api/project-plans/waiting`, MCP `*_project_plan`: owner-only (`start_run` to submit until AI-134, `decide_plan`). A capped plan is stored on the project (not via `PATCH`) and creates no ticket; approval makes at most 10 epics, recording each so a retry doesn't duplicate. Untrusted text.
- **Owner-only rules (AI-19):** one policy, `can(actor, action, project)` in `packages/domain/src/permissions.ts`, decides force move, reopen, cancel, archive, start a run, answer, promote an assumption, accept a held gap, decide a plan, pick the worker, project settings (config-change decisions included), clearing a quota idle and submitting a brief; agents and the system get `forbidden` (403). Every `user:<uid>` is the owner today (only allow-listed users pass `/api` and `/mcp` auth), so the allow-list is the trust boundary until AI-18: Project members. History stores the Firebase uid, not the email; refusals log actor and action (`owner-only action refused`); the builds-switch log records the actor. Stored `andy` reads as the owner (no migration).
- **In-flight view (ADR-0080):** `GET /api/projects/:id/in-flight` and MCP `list_in_flight` are read-only, allow-listed and scoped to one project. They return per-ticket run metadata (branch, PR, touches, reserved ADR number); titles are untrusted, rendered as text. The ADR number is parsed as digits from the default branch's index; prompts get only the number. `touches` match only a bounded glob subset, no regular expressions; anything else overlaps (no ReDoS).
- **Setup checklist (AI-95):** `GET /api/projects/:id/setup` is read-only and allow-listed. It checks files on the project's first repo with the existing App installation token (no new credential), a fixed 14 code-host calls a read, cached 5 minutes in-browser. Code-host errors are clipped to 200 characters, rendered as text.
- **Config proposals (ADR-0097):** `POST /api/projects/:id/config-proposals/sweep`, `GET /api/config-changes`, `POST /api/config-changes/:id/accept` and `/reject`, the inbox control and MCP `list_config_changes`, `sweep_config_proposals`, `accept_config_change`, `reject_config_change`, allow-listed; deciding is owner-only (the project-settings rule). A sweep only writes pending `ConfigChange`s (per project: one a minute per instance, 5 per sweep, 10 pending, checked in the write's transaction). Accepting only records agreement; nothing edits `AGENTS.md` or a procedure. Review finding titles are untrusted agent text: URLs become "link removed" and every character but letters, digits, spaces and plain punctuation is dropped, so no Markdown, HTML, mention or control character reaches proposed text; the UI shows it as plain text. The findings writer (a new entry point) and its threat-model rows come with ADR-0097 PR B.
- **Project brief (AI-107):** `POST /api/projects/:id/brief`, MCP `submit_brief`, owner-only; answers capped. The App commits only `docs/product/brief.md` on a new random-tailed `brief/` branch (deleted on a failed commit; never `.github/`, `.claude/`, `.` or `..`) and opens a PR Andy merges. 5 an hour.
- **Night launch (AI-120):** `GET`/`POST …/tickets/:id/night`, `…/night/stop`, MCP `night_status`/`launch_night`/`stop_night`, allow-listed; owner-only launch/stop (`start_run`), refused with a story open; budget capped (`NIGHT_LIMITS`); ≤50-story reads; MCP launch ungated (M4.18). Questions: plain text.
