## Credentials and identities

| Identity / secret                     | Grants                                                                                                                                                                                              | Usable from                                                          |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| MCP OAuth codes and tokens (ADR-0039) | Code (60 s, single use, PKCE-bound): one token exchange. Access token (1 h): `/mcp` as Andy. Refresh token (30 days, rotated on use): new access tokens. Re-checked against the allow-list each use | Whoever holds them: Claude (Anthropic stores them for the connector) |

- **Worker (ADR-0082):** `PUT /api/projects/:id/tickets/:id/worker` and MCP `set_worker`, `set_default_worker`, behind the same allow-list as every other route and tool. They store a choice from a fixed list, recorded as the signed-in user. Switching to an agent can start a build only under the existing `buildEnabled`, `autoBuild` and run caps. Agent runs can't reach them.
- **Owner-only rules (AI-19):** one policy, `can(actor, action, project)` in `packages/domain/src/permissions.ts`, decides force move, reopen, cancel, archive, start a run, answer, promote an assumption, accept a held gap, decide a plan, pick the worker, project settings, clearing a quota idle and submitting a brief; agents and the system get `forbidden` (403). Today every `user:<uid>` actor is the owner, because only allow-listed users get past `/api` and `/mcp` auth: the allow-list stays the trust boundary until AI-18: Project members. History stores the Firebase uid, not the email; refusals log the actor and action (`owner-only action refused`), and the builds-switch log now records the actor instead of the email. Stored `andy` reads as the owner (no migration).
- **Ideation (AI-114, ADR-0050):** `POST /api/projects/:id/ideate` and MCP `ideate`, behind the same allow-list and owner-only (`can`: `start_run`, as the submission stands in for the ideate agent task until AI-134). The result is checked against `IdeateOutput` (strict, capped; the outcome must match its fields; the spec path must match `specs/<slug>.md`, so no other file can be written). An epic outcome creates one epic and, with the App's credential, cuts an `ideate/<slug>-<time>` branch, commits only that spec file and opens a PR into the default branch for Andy to merge (not an agent branch, so the gate never merges it); at most 10 per instance per hour. A question outcome creates one Ideas ticket and one question, no PR. All result text is untrusted data.
- **In-flight view (ADR-0080):** `GET /api/projects/:id/in-flight` and MCP `list_in_flight` are read-only, behind the same allow-list, and scoped to one project. They return run metadata already visible per ticket (branch, PR, touches, reserved ADR number); ticket titles are untrusted text, rendered as text. The ADR number is parsed as digits from the default branch's index and enters the build prompt only as a number. Ticket and run `touches` are matched only in a bounded safe glob subset without regular expressions; anything else counts as overlapping (no ReDoS).
- **Project brief (AI-107, ADR-0053):** `POST /api/projects/:id/brief` and MCP `submit_brief`, behind the same allow-list, owner-only (`can`: `submit_brief`). The answers are schema-capped (`BriefAnswers`) and word-capped per section; each answer is flattened to one line and a leading `#` escaped, so it can't add headings. The control plane then uses the App's own credential (not a CI token) to cut a `brief/<project>-<time>` branch from the project repo's default branch, commit only `docs/product/brief.md`, and open a PR into the default branch; an existing branch is refused, never overwritten. The PR is not an agent branch, so the merge gate never merges it: Andy does. At most 5 brief PRs per instance per hour (ADR-0028). The brief is untrusted data for every agent that reads it later; the PR body carries no answer text.
