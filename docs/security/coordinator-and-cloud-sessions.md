The coordinator's scripts (`scripts/coordinator/`, AI-149) and Claude Code cloud sessions (runbook `coordinating-sessions.md` §6 and §7). Risk register: [threat-model.md](threat-model.md) (R23; this file's risks, R-AI-149a and R-AI-149b, wait for a register row). ## Risks

- **R-AI-149a: `resync` runs a PR branch's code as Andy.** A prompt-injected worker could change `lefthook.yml`, a test or a typecheck config so the pre-push hook runs its code during the coordinator's push. With no tokens in the environment it can still reach Andy's keychain GitHub login. Severity medium, open. Mitigations: the scrubs above; the same code already runs as Andy when the worker itself pushes from the same Mac. Next step: push from a separate macOS user or a container with only a push token, or have the coordinator review the branch's hook and config diff before `resync`.
- **R-AI-149b: a cloud worker acts as Andy through the connector and the App.** Injected ticket or PR text could steer a cloud worker to answer a question, approve a plan or move a ticket as Andy, or to push a harmful branch. Severity medium, open, until AI-151 records what the App and the connector can do. Mitigations: the connector's approval prompt on first use _(untested)_; every branch still passes CI, both review agents and ADR-0120's "Andy keeps" rules; no secrets in the environment, so a compromised VM holds only the session's own access; network "Limited". Residual: package-manager hosts stay reachable, so data could leave in a request to one.
