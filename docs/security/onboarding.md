# Threat model: setup checklist and onboarding steps

A project's setup reads (AI-95, AI-381). PRs changing them update this file. Others: [ui-and-mcp.md](ui-and-mcp.md).

| Entry point                                                         | Authn/authz                                        | Notes                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/projects/:id/setup`, MCP `project_setup`                  | Allow-listed (`/api`, `/mcp`)                      | Read-only. The first repo's files with the App token (no new credential): 15 code-host calls, cached 5 min in the browser. Errors clipped to 200 characters, shown as text                                                                                                                                |
| `GET /api/projects/:id/onboarding`, `project_setup`'s `onboarding`  | Allow-listed                                       | The repo, 5 folder listings, `rulesets`, environment `agent` and its branch rules: GET only, inside the repo (`readRepoSetting`'s checked paths), the App's existing permissions, at most 9 calls, cached 60 s per project (refresh at most every 10 s). Never Actions settings, secrets or a token value |
| `POST /api/projects/:id/onboarding/marks`, `project_setup`'s `mark` | Owner-only (`change_project_settings`); agents 403 | Stores who and when (`setupMarks`); never overrides a live "not yet". Commands are built from the stored repo name (`RepoName` characters only) and shown as text; nothing runs.
