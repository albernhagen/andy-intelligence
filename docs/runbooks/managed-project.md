# Runbook: onboard a managed project (Andy)

Every hand step to give a repo its own project in the control plane, so agent tasks (refine, plan, build) run there. A **managed repo** is a repo registered on a project other than `AI`; its `agent-run.yml` calls this repo's executor (ADR-0096: Managed repos call one executor). This page orders the steps and links the runbooks that hold the detail. About 30 minutes.

## Limits: check these first

| The repo must…                               | Why                                                                                                                                                                   |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use pnpm, with `pnpm-lock.yaml` and `.nvmrc` | The executor installs pnpm and Node only when those files exist. Other toolchains get no install step: a build agent can edit code but can't run the project's checks |
| Be public (on GitHub Free)                   | Private repos get no rulesets, environments or code scanning, so no `protect-main` and no `main`-only `agent` environment                                             |
| Have default branch `main`                   | Dispatch refuses any other default branch                                                                                                                             |
| Be the project's only repo                   | Agent tasks run in the project's first repo only                                                                                                                      |

## Steps

| #   | Do                                                                                                                                                                                                                                                                             | Detail                                                             |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| 1   | Create or pick the repo: `gh repo create albernhagen/<name> --public`. A new, empty repo: run `onboard` now (pushes the baseline and starter to `main`, applies the settings); step 4 is then done.                                                                            | [`onboard-a-repo.md`](onboard-a-repo.md) §3 (new) or §4 (existing) |
| 2   | Install the GitHub App on the repo: Settings → GitHub → **Install on repos** → add it.                                                                                                                                                                                         | [`github-app.md`](github-app.md) §3                                |
| 3   | Create the project with that repo: Add project → name, key, repo. This opens the repo to dispatch and the push grant. The App opens a baseline PR, or a Needs-you ticket if there is nothing to add (move it to Done) or the repo is empty (run `onboard`).                    | [`github-app.md`](github-app.md) §4                                |
| 4   | Baseline PR: run its `finish …` command (adds `agent-run.yml` and the other workflows the App can't write), review, merge. Then `apply --dry-run`, `apply`, `check` (exit 0).                                                                                                  | [`onboard-a-repo.md`](onboard-a-repo.md) §2                        |
| 5   | **Allow reusable workflows.** Repo → Settings → Actions → General: **Allow all actions and reusable workflows**, and Workflow permissions **Read repository contents**. `apply` sets both; check them here, because `agent-run.yml` can't call the executor without the first. | No other runbook has this step                                     |
| 6   | Reviewer token as a repo secret: `claude setup-token`, then `gh secret set CLAUDE_CODE_OAUTH_TOKEN --repo albernhagen/<name>`. The review agents run on PR branches and read it.                                                                                               | [`onboard-a-repo.md`](onboard-a-repo.md) §3 step 1                 |
| 7   | Agent tasks' token: environment `agent`, `main` only, with its own `CLAUDE_CODE_OAUTH_TOKEN`.                                                                                                                                                                                  | [`agent-environment.md`](agent-environment.md) steps 1 to 3        |
| 8   | Run one refine on a ticket in the new project. In the repo's Actions run, the `agent` job shows environment `agent` and "Check the model credential" passes.                                                                                                                   | [`agent-environment.md`](agent-environment.md) step 4              |
| 9   | Turn **Builds** on in the project's settings (the app only, no MCP tool). The setup checklist shows Repo connected, Baseline merged and Threat model started done; the other two stay "not yet" until M6.                                                                      | —                                                                  |

## If it fails

| Symptom                                                     | Fix                                                                                                                                                                                                      |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Run fails: "the App isn't installed on …"                   | Step 2                                                                                                                                                                                                   |
| Run fails: "agent tasks need the default branch to be main" | Rename the default branch to `main`                                                                                                                                                                      |
| `agent-run.yml` fails before the executor starts            | Step 5; an account-wide Actions policy can override the repo's setting. If the error names SHA pinning (`apply` requires it; the caller uses `@main`, untested): stop and decide, don't just turn it off |
| "Check the model credential" fails                          | Step 7 (or step 6's repo secret on a private repo)                                                                                                                                                       |
| Build PR's checks fail on install                           | The repo isn't pnpm (Limits)                                                                                                                                                                             |
