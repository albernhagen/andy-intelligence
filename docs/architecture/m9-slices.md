# M9: Add Jules + model routing — slices

Slice table for [milestones.md §M9](milestones.md#m9-add-jules--model-routing). Epic: AI-225: M9: Add Jules + model routing. Each ticket holds its acceptance criteria, out of scope and full `touches`. **Risk** is the merge class from ADR-0092: medium = the coordinator may merge; high = Andy merges.

**Already built, not sliced:** `Route`, `TierKey`, `ProviderKey`, `HarnessKey` (`entities/common.ts`); size → tier → route in `domain/tiers.ts` (two Claude routes, hard-coded); `overrides.tier` and `overrides.modelPin`; the draft `Executor` port and its contract suite, passed by the GitHub Actions executor; quota readings with a `daily_tasks` window; `ConfigChange` audit; the PR webhook and run watchdog.

**Design in one paragraph** (recorded by M9.1 as ADR-0128, proposed): routing is one stored `RoutingConfig`: providers (enabled, reserve, warn and pause), tiers (ordered routes), and step → tier. Global is the ceiling; a project can only narrow it. A pure resolver picks a step's first route that is enabled and compatible (`claude-code` with `claude-sub`, `jules` with `google-sub`, `opencode`/`direct` with `openrouter`). The default config reproduces today's two routes, so nothing changes until Andy edits it. Jules is a second `Executor`: it starts a Jules session that opens its own PR, and the PR webhook finishes the run (ADR-0018). google-sub quota is counted from the Jules tasks the control plane started. Quota-aware fallback to the next route stays in M10: Paid models + spend caps.
