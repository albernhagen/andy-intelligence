# 0071 — Build sandbox: `.git` writable, a live sandbox check before the agent, placeholders dropped

Built in AI-42: Build sandbox: every Bash call fails on .git/config.lock, and mount placeholders leak into the PR. Amends ADR-0063: Build run protocol.

## Context and Problem Statement

The live sandbox proof (runbook `agent-runs.md` §9, 2026-11-06, `docs/build-log/2026-11-06-sandbox-proof-failed.md`) failed. The profile's `filesystem.denyWrite: ["<checkout>/.git"]` bound `.git` read-only; Claude Code's sandbox then couldn't create its placeholder at `.git/config.lock`, so every Bash call failed (`bwrap: Can't create file at …/.git/config.lock: Read-only file system`). The `bwrap --ro-bind / / … true` step had printed "Sandbox ready" anyway: it never ran Claude Code's own wrapper. Seven empty placeholders the sandbox binds for protected files the repo lacks (`.gitmodules`, `.npmrc`, `.yarnrc`, `.yarnrc.yml`, `bunfig.toml`, `package-lock.json`, `yarn.lock`) stayed behind and reached the PR.

Claude Code's sandbox docs (code.claude.com/docs/en/sandboxing, "Protected paths") already write-deny, inside the working directory, "`hooks` and `config` inside `.git`", shell startup files, `.gitconfig`, `.mcp.json` and `.claude` settings; the list isn't configurable short of `filesystem.disabled`. On Linux a missing protected file gets "a 0-byte read-only placeholder" that "the sandbox removes … afterward", except when a session is killed or exits mid-command.

## Decision Outcome

| Topic         | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.git`        | No `denyWrite` on `.git`: the agent's Bash may write the index, objects, refs and lock files (git and `pnpm test` need them). `.git/config` and `.git/hooks` stay read-only by the sandbox's own protected paths; the Edit tool keeps `Edit(//**/.git/**)` denied. A read-only `.git/commondir` or similar can't be added: the sandbox would bind an empty placeholder there, and git dies on an empty `commondir`. After the agent, the collect step compares the paths that steer git (`GIT_SENSITIVE`: `config`, `config.worktree`, `commondir`, `gitdir`, `hooks`, `info`, `modules`, `worktrees`, `objects/info/alternates`, `objects/info/http-alternates`) with the copy taken before the agent, fails the run if any changed, and restores the whole `.git` from that copy before anything else (checkout's post step) runs git there. Collection already runs git from the copy; the publish job checks out the base commit fresh. |
| Sandbox check | Replaces the `bwrap` "Sandbox ready" claim. Before the agent, one extra run of the same pinned `claude-code-action` under the same managed settings and env, with a fixed prompt (no ticket text), Haiku, 3 turns, 5 minutes, runs one command through Bash: `git update-index --refresh` (takes `index.lock`), `git status`, a test that the model and GitHub credential variables are empty, and a write of a nonce into the checkout, chained with `&&`. The verify step (`executor-sandbox.mjs verify-check`) passes only if the action's execution log shows exactly that command, one Bash call, no error, no other tool, and the marker holds the nonce; else the job fails before the agent runs and the report says "The sandbox check failed". The check's placeholders are dropped before the agent. The `bwrap` call stays as a runner diagnostic.                                                                              |
| Placeholders  | Before `git add -A`, the collect step runs `executor-publish.mjs drop-placeholders`: a listed protected file (`SANDBOX_PLACEHOLDERS`: the seven above and the documented ones) is deleted and logged if it is an empty regular file, not a symlink, not below a symlinked directory, and not in the manifest of workspace files taken before the sandbox check. Anything else stays in the change and meets the publish checks as before.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

### Consequences

- Good: the agent can run git and the project's checks; a sandbox that breaks Bash, or exposes a credential variable, stops the run before the agent spends anything; the check exercises the real wrapper, not a stand-in.
- Accepted: the check is a model call (about a cent with Haiku) on every build run, which ADR-0063 had ruled out. The agent can now write `.git` internals other than `config` and `hooks`; a change to one that steers git fails the run. An agent that deliberately creates an empty listed file loses it, with a log line.
- Bad: the check depends on the model running one command verbatim; if it rewrites or refuses it, the run fails (fail closed). During the agent run, Claude Code's own git calls outside the sandbox (with the model credential in its environment) could read a planted `commondir` or alternates before the collect step catches it; its git status snapshot is taken at session start, before the agent writes anything. The placeholder list follows Claude Code's undocumented behaviour; a new protected file shows up as an empty file in a PR until it is added.
