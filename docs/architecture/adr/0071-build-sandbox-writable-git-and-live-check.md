# 0071 — Build sandbox: `.git` writable, a live sandbox check before the agent, placeholders dropped

Built in AI-42: Build sandbox: every Bash call fails on .git/config.lock, and mount placeholders leak into the PR. Amends ADR-0063: Build run protocol.

## Context and Problem Statement

The live sandbox proof (runbook `agent-runs.md` §9, 2026-11-06, `docs/build-log/2026-11-06-sandbox-proof-failed.md`) failed. The profile's `filesystem.denyWrite: ["<checkout>/.git"]` bound `.git` read-only; Claude Code's sandbox then couldn't create its placeholder at `.git/config.lock`, so every Bash call failed (`bwrap: Can't create file at …/.git/config.lock: Read-only file system`). The `bwrap --ro-bind / / … true` step had printed "Sandbox ready" anyway: it never ran Claude Code's own wrapper. Seven empty placeholders the sandbox binds for protected files the repo lacks (`.gitmodules`, `.npmrc`, `.yarnrc`, `.yarnrc.yml`, `bunfig.toml`, `package-lock.json`, `yarn.lock`) stayed behind and reached the PR.

Claude Code's sandbox docs (code.claude.com/docs/en/sandboxing, "Protected paths") already write-deny, inside the working directory, "`hooks` and `config` inside `.git`", shell startup files, `.gitconfig`, `.mcp.json` and `.claude` settings; the list isn't configurable short of `filesystem.disabled`. On Linux a missing protected file gets "a 0-byte read-only placeholder" that "the sandbox removes … afterward", except when a session is killed or exits mid-command.

## Decision Outcome

| Topic         | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.git`        | No `denyWrite` on `.git` itself: a read-only `.git` is the bug. **Denied** (profile `denyWrite`), the paths that steer git: `commondir`, `config.worktree` (another repository's config), `HEAD`, `packed-refs`, `refs/` (what is checked out), `info/` (attributes, exclude), `objects/info/` (alternates), `modules/`, `worktrees/`; the sandbox itself denies `config` and `hooks`, and the Edit tool keeps `Edit(//**/.git/**)`. The Prepare step creates each one first (`commondir` as `.`, which points at `.git` itself; the rest empty), so the sandbox binds a real file or directory read-only: a missing path would get an empty placeholder, and git refuses an empty `commondir`. **Writable**, because git and `pnpm test` need them: the index, lock files, loose objects and logs, and new files in `.git` itself (state such as `ORIG_HEAD`). **Restored:** the pristine copy goes back right after the sandbox check (verify step, `if: always()`) and after the agent (collect step), each time after `check-git` compares the steering paths (`GIT_SENSITIVE`) and fails the job on a change. A skipped agent never wrote `.git`; the check's restore already ran. Not a throwaway `GIT_DIR` for the agent: Claude Code has no environment setting for sandboxed commands only (`env` reaches every subprocess; `sandbox.credentials.envVars` only removes or masks), so its own git would read the agent-writable copy, whose `config` the sandbox doesn't protect. |
| Sandbox check | Replaces the `bwrap` "Sandbox ready" claim. Before the agent, one extra run of the same pinned `claude-code-action` under the same managed settings and env, with a fixed prompt (no ticket text, no nonce; "don't read any file"), Haiku, 3 turns, 5 minutes, runs one command through Bash in the checkout (the agent's working directory, so its writability is what gets tested): `git update-index --refresh` (takes `index.lock`) and `git status`, then it writes facts to a file: the nonce (from the step's env only), `/proc/1/cmdline` and the env variable names. The workflow judges (`executor-sandbox.mjs verify-check`): the execution log must show that command (ends trimmed, blanks collapsed) as the one Bash call, without error and no other tool; the nonce must match, PID 1 differ from the runner's, and no credential variable appear. Then the checkout must be clean (`git status` from the pre-agent `.git`), else the job fails naming what the check left. Any failure stops the job before the agent; the report says "The sandbox check failed". The `bwrap` call stays as a runner diagnostic.                                                                                                                                                                                                                                                                                                                                                        |
| Placeholders  | Before `git add -A`, as defence in depth (the check already fails on a dirty checkout), the collect step runs `executor-publish.mjs drop-placeholders`: a listed protected file (`SANDBOX_PLACEHOLDERS`: the seven above and the documented ones) is deleted and logged if it is an empty regular file, not a symlink, not below a symlinked directory, and not in the manifest of workspace files taken before the sandbox check. Anything else stays in the change and meets the publish checks as before.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

### Consequences

- Good: the agent can run git and the project's checks; a sandbox that breaks Bash, or exposes a credential variable, stops the run before the agent spends anything; the check exercises the real wrapper, not a stand-in.
- Accepted: the check is a model call (about a cent with Haiku) on every build run, which ADR-0063 had ruled out. The agent can write git's working files in `.git`, not the paths that steer it. An agent that deliberately creates an empty listed file loses it, with a log line.
- Bad: the check depends on the model running one command verbatim; if it rewrites or refuses it, the run fails (fail closed). A second `claude-code-action` invocation in one job, and binding the denied `.git` paths, are proven only live. During the agent run, Claude Code's own git calls outside the sandbox (with the model credential in its environment) still read the agent-writable index, objects, logs and state files; none of those makes git run code or read another config without a command that acts on them (e.g. `rebase --continue`). Its git status snapshot is taken at session start, before the agent writes anything. The placeholder list follows Claude Code's undocumented behaviour; a new protected file shows up as an empty file in a PR until it is added.
