# 0063 — Build run protocol: dispatcher, sandboxed Bash, publish job with one token per run

Built in M1.8a: Build run (ticket AI-3: M1.8: Build + gate, first half; ADR-0060 split it). Fills in ARCHITECTURE §4.1 (Ready → In progress), §7.2 and §9 where they left choices open; builds on ADR-0051 (executor run protocol), ADR-0054 (refine protocol) and ADR-0055 (watchdog and retry).

## Context and Problem Statement

A Ready ticket had nothing to build it. The build step needs what refine never had: Bash (to run the project's checks) and a way to get its change into a PR. ADR-0051 noted that Read denies don't stop `cat /proc/self/environ`, so Bash in the job that holds the model credential reaches it; the runner user also has passwordless `sudo`. The agent's job must stay without an OIDC token and without a write token. Open choices: who starts a build, how Bash is contained, how the change leaves the agent's job, who pushes and with which credential, and what a run records.

### Consequences

- Good: Ready tickets become PRs without Andy, but only where he turns it on; the agent's job still has no OIDC or write token; the token that can push is bound to one build run; a change to a trust anchor is stopped twice (edit time, publish time) and a third time by GitHub for workflows; every attempt's work survives for inspection.
- Accepted: the AppArmor profile lets any `bwrap` on the (ephemeral) runner create user namespaces unconfined. There is no in-CI canary of the sandbox before the prompt: it would need a model call or a third-party sandbox binary in the job that holds the credential. The `buildEnabled` gate makes the proof a deliberate, recorded step instead.
- Bad: the sandbox, the env scrub and managed-settings `sandbox` keys are proven only by a live run (runbook `agent-runs.md` §9); until then they are documented intent. The scrub relies on the CLI version the action installs. The grant is read-then-write: two calls racing in the same instant from the same workflow run could both pass (both are the platform's own jobs). The prompt, the plan and the PR text are public in this repo's logs and PRs (R22). Agent PRs can't change `.github/`, `platform/actions/` or the review scripts; Andy does those. Dependencies come only from the npm registry, so other stacks wait for M5.
