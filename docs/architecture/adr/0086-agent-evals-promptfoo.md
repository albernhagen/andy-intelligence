# 0086 — Agent evals: promptfoo over Claude Code, cases as data, runner from the base commit

Built in AI-6: M1.17: Agent evals v1. ADR-0040: Close gaps against the AI-native SDLC playbook says changes to procedures, prompts and agent rules pass an eval suite before merge, tool chosen in the slice. Andy's answers on AI-6 (2026-11-08 and 10) set the tool (promptfoo, with a short ADR), the thresholds (90% pass rate; input tokens +20% over a committed baseline; each case once, no retries) and the model source (the subscription token by default, switchable to an API key with a hard cap). This ADR records how.

## Decision Outcome

| Topic        | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tool         | promptfoo CLI, pinned (`PROMPTFOO_VERSION` in `scripts/evals/config.mjs`) and run with `npx -y` like `firebase-tools` in `test:firestore`: no dependency in `package.json`, no lockfile change. The `Evaluator` adapter (`scripts/evals/promptfoo-evaluator.mjs`) wraps it and passes the port's contract suite.                                                                                                                                                                                                                                                          |
| Model calls  | A custom promptfoo provider runs each case through the Claude Code CLI at the executor's pinned version, with the production procedure, schema (`--json-schema`), model and read-only tools (`--tools Read,Glob,Grep`), in a workspace holding only the case's inputs. Reads outside it need a permission nobody grants.                                                                                                                                                                                                                                                  |
| Cases        | Plain JSON in `platform/evals/cases/` with a fixed check vocabulary (`finding`, `no-finding`, `max-findings`), validated strictly; plus promptfoo's `is-json` against the agent's schema, read at run time. A case can't carry code: promptfoo's inline `javascript` assertions are never written from case data.                                                                                                                                                                                                                                                         |
| Token metric | Input tokens of the case's **first** model request (system prompt, `AGENTS.md`, procedure, inputs): what ADR-0046 budgets, and stable from run to run. The total over all turns varies with how much the agent reads and would flap.                                                                                                                                                                                                                                                                                                                                      |
| Trust        | The live job holds the model credential, so the runner comes from the PR's **base** commit; the PR's procedures, `AGENTS.md` and cases are read from git objects as data (symlinks refused). Only the selected source's credential reaches promptfoo and the CLI, each in an env with nothing else (PATH, locale, that credential). `agent-evals` never accepts the stub model; only the plumbing job uses it. The summary holds numbers, case ids and fixed messages, never model text; no output is uploaded. A stub-model job runs the PR's own runner with no secret. |
| Quota        | The subscription path reads the `rate_limit_event` each case emits; at the reserve (80%, the dispatcher's pause level) later cases are skipped and the check passes as `skipped`, unless a case that ran failed. A workflow can't read the control plane's quota level without new credentials, so at most one case runs past the reserve. The scale (`utilization` 0-1) and rounding match `parseRateLimits` in the domain (a test holds them equal); a reading over 200% fails the case instead of skipping.                                                            |
| Not loaded   | `.claude/**` changes trigger the suite, but cases never load the PR's `.claude` settings or hooks (they would run PR code with the credential).                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Scope (v1)   | The two review agents. Refine and build cases wait: refine needs the run-context input and a repo tree, build needs the write sandbox.                                                                                                                                                                                                                                                                                                                                                                                                                                    |

### Consequences

- Good: a procedure or `AGENTS.md` change is tested before merge; a token jump fails like a pass-rate drop; nothing new in the lockfile.
- Bad: npx downloads promptfoo on each run (about 1 GB, a minute on CI); its transitive dependencies aren't locked and run with the credential in the live job; Dependabot doesn't bump it. A PR that edits its own cases or baselines can weaken its check (threat model R-AI-6).
