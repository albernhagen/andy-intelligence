# 0086 — Agent evals: an in-repo runner over Claude Code, cases as data, runner from the base commit

Built in AI-6: M1.17: Agent evals v1. ADR-0040: Close gaps against the AI-native SDLC playbook says changes to procedures, prompts and agent rules pass an eval suite before merge, with the tool chosen in the slice. Andy's answers on AI-6 set the thresholds (90% pass rate; input tokens +20% over a committed baseline; each case once, no retries) and the model source (the subscription token by default, switchable to an API key with a hard cap). He first chose promptfoo, then dropped it on 2026-11-11 ("Yes, drop it"). This ADR records the result.

## Decision Outcome

| Topic         | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tool          | A small in-repo runner (`scripts/evals/`, plain Node, no dependency): it runs each case, checks the output against the agent's schema (`schema-check.mjs`, the JSON Schema subset the review schemas use; any other keyword is refused) and the case's checks. Its `Evaluator` adapter (`evaluator.mjs`) passes the port's contract suite. Tests use the project's vitest.                                                                                                                          |
| Not promptfoo | Rejected: 80 direct and 24 optional dependencies (cloud SDKs, a web server, telemetry), about 1 GB and 5,500 requests per run through `npx`, unlocked transitive dependencies in the process holding the credential, and none of its features used: the checks, the model call and the schema check were already our own code. A locked devDependency would have put all of that in every `pnpm install`.                                                                                           |
| Model calls   | Each case runs through the Claude Code CLI at the executor's pinned version, with the production procedure, schema (`--json-schema`), model and read-only tools (`--tools Read,Glob,Grep`), in a workspace holding only the case's inputs. Reads outside it need a permission nobody grants.                                                                                                                                                                                                        |
| Cases         | Plain JSON in `platform/evals/cases/` with a fixed check vocabulary (`finding`, `no-finding`, `max-findings`), validated strictly. A case can't carry code.                                                                                                                                                                                                                                                                                                                                         |
| Token metric  | Input tokens of the case's **first** model request (system prompt, `AGENTS.md`, procedure, inputs): what ADR-0046 budgets, and stable from run to run. The total over all turns varies with how much the agent reads and would flap.                                                                                                                                                                                                                                                                |
| Trust         | The live job holds the model credential, so the runner comes from the PR's **base** commit; the PR's procedures, `AGENTS.md` and cases are read from git objects as data (symlinks refused; file names not `<id>.json` are never echoed). The credential reaches only the Claude Code CLI, in an env holding PATH, locale and that credential. `agent-evals` never accepts the stub model; only the plumbing job uses it. The summary holds numbers, case ids and fixed messages, never model text. |
| Quota         | The subscription path reads the `rate_limit_event` each case emits, with the domain's rules (`parseRateLimits`; a test holds them equal). At the reserve (80%, the dispatcher's pause level) later cases are skipped and the check passes as `skipped`, unless a case that ran failed. A reading over 200% fails the case: the scale isn't a 0-1 fraction. The summary shows the highest reading, or that there was none.                                                                           |
| Not loaded    | `.claude/**` changes trigger the suite, but cases never load the PR's `.claude` settings or hooks (they would run PR code with the credential).                                                                                                                                                                                                                                                                                                                                                     |
| Scope (v1)    | The two review agents. Refine and build cases wait: refine needs the run-context input and a repo tree, build needs the write sandbox.                                                                                                                                                                                                                                                                                                                                                              |

### Consequences

- Good: a procedure or `AGENTS.md` change is tested before merge; a token jump fails like a pass-rate drop; nothing new in the lockfile and nothing downloaded but the pinned Claude Code CLI.
- Bad: model-graded scoring, red-teaming or a results viewer would need building or a tool later. Neither the quota scale nor the token metric has been seen on a live run before merge (runbook `agent-evals.md` §5). A PR that edits its own cases or baselines can weaken its check (threat model R-AI-6).
