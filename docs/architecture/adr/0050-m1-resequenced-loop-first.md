# 0050 — M1 re-sequenced: run the loop first, then harden; Claude-only through M6

Decided by Andy, 2026-11-04, after a review of the docs, the code on `main` and the remaining plan.

## Context and Problem Statement

Fifteen of the twenty-one M1 slices are merged, and all six left (M1.6: Claude Code executor, M1.7: Refinement, M1.8: Build + gate, M1.9: Quota capture, M1.17: Agent evals v1, M1.18: Plan step) are the loop itself: no agent has built anything through the system yet. ADR-0040 put two gates before the first agent PR (a plan step with approval, a required evals check). The plan then adds a second harness, a paid-model gateway and a weekly model scout (M3, M4) before epics and releases. The two biggest unknowns, headless Claude Code billing and quota capture, are still unverified. Andy is the throughput limit: questions, plan approval and merge are three synchronous waits per ticket.

### Consequences

- Good: a real agent PR weeks earlier; one gate per ticket (the PR) for S and M; evals seeded from real runs instead of guesses; no vendor machinery until it is needed; Sonnet for small work from the first run.
- Bad: the first runs have no evals safety net; an auto-merged PR can land a bug on `main` (revert is cheap; prod is gated); with plan approval off, Andy sees the plan with the code, not before it; Jules's free quota and cheaper paid models stay unused until after M6.
