# 0040 — Close the gaps against Anthropic's AI-native SDLC playbook

Decided by Andy, 2026-11-03. Changes the M1: First end-to-end flow plan (ADR-0021) and the adversarial review procedure (ADR-0026).

## Context and Problem Statement

andy-intelligence is an agentic development platform, so it should follow Anthropic's guidance on running a software lifecycle with agents: [The AI-native SDLC playbook](https://claude.com/resources/articles/the-ai-native-sdlc-playbook) (read 2026-11-03). The playbook is a loop of committed artifacts (intent → spec → plan → diff + tests → reviewed PR → incident record), with humans owning intent, acceptance, risk and release.

Most of it is already in the plan: tickets with EARS acceptance criteria and refinement questions (intent and spec), `AGENTS.md` plus procedures as skills, edit/commit/push hooks (ADR-0027), security and adversarial review on every PR where the author can't approve (ADR-0025, ADR-0026), a separate agent identity through the GitHub App (M1.5: GitHub App + project registration), human gates, caps on anything that scales, and the weekly system security review. Prod monitoring that opens tickets stays deferred (§1 non-goals).

Five gaps matter before agents write real code.

### Consequences

- Good: changes to procedures and prompts get tested like code; agents prove their own work; Andy approves the risky part (the plan) before the code; reviews check the ticket was actually done; headless runs can't read secrets or edit protected paths.
- Bad: two more M1 slices; evals and plan runs spend subscription quota (both capped in their slices); M/L tickets wait for a plan approval. The acceptance-criteria pass trusts the PR summary written by the build agent until agents get read access to the API (M2).
