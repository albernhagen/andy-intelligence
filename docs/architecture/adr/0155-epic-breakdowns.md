# 0155 — Epic breakdowns: an agent drafts an epic's tickets as a proposal Andy approves

AI-383: Break an approved milestone's epic into tickets for Andy's approval. Proposed as P6 by spike AI-364 and approved by Andy on 2026-11-25. Plan-project turns an approved plan into one milestone and one epic per milestone (ADR-0149). Nothing turned an epic into tickets, so for a managed project, which has no coordinator session, Andy wrote every ticket himself.

## Decision Outcome

| Topic             | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Step              | A new agent step, `plan-epic`, for one top-level epic whose milestone is **approved**. It runs read-only on the project's repo, by `platform/procedures/plan-epic.md`, and returns `plan-epic.schema.json`: a summary and up to 12 drafted tickets. Each ticket has title, type (never epic), size and reason, body, acceptance criteria, touches, and `blockedBy` as 0-based sibling indexes. The run belongs to the epic, so its comments land in the epic's history. It is strong tier, 40 turns, 45 minutes, on the cloud executor only, and never retried automatically.                                                                                                                                                                                                                         |
| Data model        | One `EpicBreakdown` per epic, stored apart from the ticket (`projects/{p}/epicBreakdowns/{epicId}`, port `EpicBreakdownStore`). It holds the status (the project plan's: proposed, approving, approved, rejected), the proposal, who proposed and who decided, Andy's note, and the created ticket ids. It is kept off the ticket because every ticket write logs a full before-and-after diff, and a 12-ticket proposal would be copied into the epic's history at each status change.                                                                                                                                                                                                                                                                                                               |
| Approval          | Approving creates the tickets under the epic in Ideas, in order (a new ticket's default; nothing builds and refine doesn't start). Then the sibling indexes become `blockedBy` keys. Approval is resumable, like a project plan's: each created id is recorded as it lands, and a retry adopts only a ticket that approval itself created (same title and body, created by the approver since it started), never one the epic had. One approval runs at a time, across instances: it first wins a stamp-checked write, then holds a 2-minute lease renewed after each ticket. A crashed approval's lease runs out, and approving again resumes. A rejected agent result fails the run and flags the epic Needs-you. Sending back records Andy's note, and the next drafting task's prompt carries it. |
| Refusals          | The step refuses, with the reason: a ticket that isn't a top-level epic, an epic that is archived, cancelled or done, a milestone that is not approved, a breakdown already waiting, and one already approved (re-planning is out of scope).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Caps (ADR-0028)   | 12 tickets per proposal. One drafting task per epic in flight. 3 dispatched drafting tasks per epic in all. Plus the project's dial, the global cap and the spend reservation. At a cap, the start is refused with a message saying which cap.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Parity (ADR-0148) | REST under `…/tickets/{id}/breakdown` and MCP `start_epic_breakdown`, `submit_epic_breakdown`, `approve_epic_breakdown`, `reject_epic_breakdown`. `list_needs_me` lists waiting breakdowns as `epicBreakdowns`, and `status` counts them. A Claude session can draft by hand and submit. The web panel and inbox section follow in their own PR.                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

### Consequences

- Good: a managed project gets from approved plan to tickets without Andy writing them. Approval reuses the project plan's lifecycle, and blocker linking is shared with refine's split.
- Bad: a new store and executor step to maintain. The executor workflow and profile are kept paths, so the PR that adds them is Andy's to merge.
- Risk: drafted text is untrusted agent output. Each field is capped, the contract schema checks it, and the web shows it as plain text. Created tickets sit inert in Ideas until Andy moves them on. [R-AI-383](../../security/risks/R-AI-383.md).
