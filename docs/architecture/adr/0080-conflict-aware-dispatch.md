# 0080 — Conflict-aware dispatch, the in-flight view, reserved ADR numbers

## Context and Problem Statement

ADR-0047: Coordinating parallel work lists four collision fixes. ADR-0079: Dispatch caps lets several build runs start at once, in rank order, with no regard for what they edit; the coordinator session kept parallel workers apart by hand ("two workers never own the same file") and reserved ADR numbers by hand in briefs. ADR-0058 says Ready is a queue that skips tickets whose `touches` (areas or path globs a ticket expects to edit) overlap a run in flight. This ADR builds three of ADR-0047's fixes; sync runs when `main` moves are a later ticket.

## Decision Outcome

| Rule               | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Where                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Overlap            | Two `touches` lists overlap when any glob of one matches or contains any glob of the other. A literal path also covers everything under it (a directory). Two globs overlap unless their fixed prefixes (the part before the first `*`, `?`, `[` or `{`) diverge: this errs towards overlap, which only delays a run.                                                                                                                                                        | `overlaps` in `packages/domain/src/dispatch-conflicts.ts` |
| Unknown `touches`  | An empty list is unknown and overlaps everything, on the ticket or on the run. A ticket with empty `touches` still runs when no build is in flight.                                                                                                                                                                                                                                                                                                                          | same                                                      |
| Which runs block   | Build runs in flight (queued or running, before their deadline). Refine and plan runs are read-only and never block.                                                                                                                                                                                                                                                                                                                                                         | `editingRuns`                                             |
| What a run records | `Run.touches`: the ticket's `touches` at start plus the approved plan's `files` (ADR-0050), capped at 100. Fixed for the run's life.                                                                                                                                                                                                                                                                                                                                         | `RunService.start`                                        |
| Skip               | The build dispatcher skips a Ready ticket overlapping a build in flight in the project (oldest first) and goes on down the rank order. Logged with `touches_overlap` and the blocking ticket. When it started nothing and skipped one, the project's `lastDispatch` is `touches_overlap`. A run ending dispatches again, so the skipped ticket starts then.                                                                                                                  | `BuildDispatcher`                                         |
| Status line        | A Ready ticket reads "Waiting: overlaps AI-12 in flight", computed at read time from the in-flight view with the same predicate (UI story panel and MCP `status`). No new ticket field or event.                                                                                                                                                                                                                                                                             | `ticketStatusLine`                                        |
| In-flight view     | `GET /api/projects/{id}/in-flight`, MCP `list_in_flight` (read-only), and an "In flight" panel on the board: each run's ticket key and title, step, status, branch, PR, start time, touches and reserved ADR number; project-scoped, oldest first.                                                                                                                                                                                                                           | `RunService.inFlight`                                     |
| ADR numbers        | When a build run starts, the control plane reserves one above the highest of (a) the rows of `docs/architecture/adr/README.md` on the repo's default branch and (b) every number any run in the project ever reserved. It is stored on the run (`Run.reservedAdr`) and put in the build prompt ("Your ADR number, if you need one"). A finished or failed run frees nothing: numbers are never reused, so an open PR's number stays its own. A retry keeps its run's number. | `RunService.reserveAdr`                                   |
| No index           | A repo without the index, or one that can't be read, gets no number (never a guess); the prompt then says not to write an ADR and to ask in the summary.                                                                                                                                                                                                                                                                                                                     | same                                                      |
| Race               | Two concurrent starts that reserve the same number: the newer run fails like a lost slot race (ADR-0079), and the next dispatch retries.                                                                                                                                                                                                                                                                                                                                     | `RunService.start`                                        |
| Risk IDs           | New threat-model risk IDs carry the ticket key (`R-AI-42`), as ADR-0047 decided; the build procedure says so.                                                                                                                                                                                                                                                                                                                                                                | `platform/procedures/build.md`                            |

New Run fields have defaults, so older documents read as before: no schema version bump. Runs started before this change have empty `touches`, so they block every ticket until they end.

### Consequences

- Good: the dispatcher does what the coordinator did by hand; Andy and any harness see what is in flight and why a ticket waits.
- Good: an ADR number written by one run can't be taken by a parallel one.
- Bad: overlap is only as good as `touches`; a ticket that edits outside its globs can still conflict (sync runs, next ticket, catch the rest).
- Bad: two-glob overlap errs wide (`apps/**/*.tsx` and `apps/web/x.ts` overlap), so some runs wait that needn't.
- Bad: reading every run of the project for the highest reservation costs one read per run per build start; fine at this scale, revisit with a counter if it grows.
- Neutral: a ticket skipped for overlap may get a plan run later than it could have (plan runs never conflict); simpler than a second rule.
