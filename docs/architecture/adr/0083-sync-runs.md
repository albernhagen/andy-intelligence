# 0083 — Sync runs: when main moves, open agent PRs merge it; caps and accounting

Built in AI-72: Sync runs. ADR-0047: Coordinating parallel work decided that when `main` moves, each open agent PR gets a short run that merges `main`, resolves conflicts and pushes, "capped like any run". This ADR records what that took beyond ADR-0047, chiefly how sync runs count against the caps of ADR-0079: Dispatch caps.

## Context and Problem Statement

With several runs at once (ADR-0079) and auto-merge to come, two green PRs built from the same `main` can each pass the gate and break `main` together. Until now the coordinator session told each worker to merge `main` after every merge, by hand. A sync run spends subscription quota like a build, so it needs the same caps (ADR-0028); but it is short, finishes work already done, and shouldn't wait behind new builds for a slot on the dial.

### Consequences

- Good: open PRs keep up with `main` without the coordinator; a stale head can't auto-merge; Andy hears only about conflicts the agent can't settle.
- Good: sync runs can't starve builds or be starved by them, and can't loop: one per PR at a time, 3 a day, none twice on a stopped head.
- Bad: each dispatch tick costs up to 40 host reads (20 PRs), and a stale PR a sync run of quota plus a Haiku check run.
- Bad: a PR that changes dependency or toolchain files never syncs on its own; Andy merges `main` into it. The executor's checks are the root package's scripts; a project without them is checked by the agent's word and the review agents only.
- Bad: the App has no `workflows` permission, so GitHub may refuse a push whose merge brings in workflow-file changes from `main`; the run fails and flags the ticket, and Andy merges by hand. A conflicted lockfile fails the dependency install before the agent; same result.
- Accepted: an App created before AI-72 doesn't receive `push` until Andy ticks it (runbook `agent-runs.md`); until then merged PRs trigger syncs, direct pushes to `main` don't.
- Accepted: other projects waiting on the global cap aren't woken for syncs, only for builds (one project until M5: Multi-project in parallel).
