# 0156 — A build gets the packages its approved plan names, resolved by a trusted job outside the sandbox

AI-386: A build gets the dependencies its plan names, installed outside the sandbox. Andy chose the shape on 2026-11-25, over "Andy adds them by hand" and "the agent installs freely".

## Context and Problem Statement

ADR-0072 installs a build's dependencies from the lockfile before the agent; inside Claude Code's sandbox `package.json`, the lockfiles and `node_modules` are read-only, so a build can't add a package and stops. A managed project starts from the starter template, so most of its early tickets need a package, and each would become a hand step for Andy.

## Decision Outcome

| Topic           | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Plan            | The plan names the packages: `packages: [{name, kind: runtime\|dev, workspace, why}]`. Name only (no version, URL, `git:`, `file:` or alias), a repo-relative workspace (no `..`), at most 5 per ticket (`PACKAGE_LIMITS`, ADR-0028). Andy sees them in the plan he approves.                                                                                                                                                                                                                                                                                                                                                  |
| Who resolves    | A new `deps` job in `claude-executor.yml`, before the `agent` job, for builds whose approved plan names packages. No `agent` environment (no model credential), no `id-token` (no OIDC, so no App token), `contents: read` for the checkout only, not persisted. The trusted script (`scripts/executor-deps.mjs`, from the platform at the workflow's own commit) re-checks the packages.                                                                                                                                                                                                                                      |
| How             | `pnpm add --lockfile-only --ignore-scripts --ignore-pnpmfile --config.minimum-release-age=10080`, per workspace and kind: the newest version at least 7 days old (the cooldown Dependabot uses), no package or project code run, no `node_modules` written. The job refuses a pnpm older than 10.16 (it would ignore the cooldown), a project setting that exempts packages from it (`minimumReleaseAgeExclude`), any change but the named workspaces' `package.json` and `pnpm-lock.yaml`, and a lockfile with a non-registry source (git, tarball, directory). A named package already installed leaves the files unchanged. |
| Hand-over       | The files go to the `agent` job as an artifact with the commit they were resolved on. The agent job refuses them unless that commit is its own and the files are exactly the expected ones, applies them after its pristine `.git` copy, then runs ADR-0072's frozen install. The sandbox and profile are unchanged.                                                                                                                                                                                                                                                                                                           |
| PR              | The manifest and lockfile change is part of the agent's change: dependency review and the lockfile-source check run on it, and the gate counts it as tooling files, so Andy merges it.                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Refusals        | Over the cap: the plan result is rejected (plan run fails, ticket flagged). Can't resolve: `deps` fails, the agent never starts, the report says pnpm's reason; the usual one retry, then Needs-you. Local runner: refused (it has no trusted install step yet).                                                                                                                                                                                                                                                                                                                                                               |
| Missing package | A build that needs a package its plan didn't name stops and lists it in `neededPackages`; the ticket says so; that plan counts as stale, and the next start writes a new plan (whatever the plan-approval policy) whose prompt lists them.                                                                                                                                                                                                                                                                                                                                                                                     |
| Updates         | Updating installed packages stays with Dependabot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

### Consequences

- Good: a build can add what it needs without loosening the sandbox; every new package is seen by Andy before it is resolved and again in the PR.
- Bad: one more job per such build (about a minute); a build that discovers a package mid-way costs a stopped run and a new plan.
- Accepted: the trusted job trusts the registry's metadata and the default branch's `.npmrc`, as ADR-0072's install does. A package's own install scripts never run here; whether they run later is the project's business (pnpm 10 runs only allow-listed build scripts).
