# 0054 — Refine run protocol: auto-start, structured output, questions once per run, auto-move to Ready

Built in M1.7: Refinement. Fills in ARCHITECTURE §4.3 and §7.2 where they left choices open; builds on ADR-0051 (executor run protocol).

## Context and Problem Statement

M1.6a's refine run returned a free-text report. M1.7 needs 1–5 questions back as records, written safely from untrusted agent output, and a ticket that reaches Ready when Andy has answered them. Open choices: how the result comes back, where the procedure lives, what stops duplicates and runaway runs, and who starts refine. Refinement is mandatory (§2), so Andy must not have to start it: the system asks him when it needs him.

## Decision Outcome

| Topic             | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Result channel    | Structured output, not free text or a file (the run is read-only: no Write tool). `platform/procedures/refine.schema.json` goes to `claude-code-action` as `--json-schema`; the action fails the run if the agent returns no match. `executor-report.mjs` sends `structured_output` as `output` (≤ 48 KB; summary cut to 4,000 characters then).                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Check             | The control plane is the check: `RefineOutput` (`@andy/contracts`) — summary ≤ 4,000 characters, 1–5 questions of ≤ 500, ≤ 5 options of ≤ 200, ≤ 5 assumptions of ≤ 300, no unknown fields. A test keeps the JSON schema's limits equal to it. A bad result fails the run with the reason; nothing is written.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Procedure         | `platform/procedures/refine.md` (vendor-neutral, ADR-0032). The workflow reads `<step>.md` and `<step>.schema.json` from the platform's commit, like the profile, and puts the procedure before the run's prompt (stable prefix, ADR-0046). The control plane's prompt holds only the role, the untrusted-data warning and the ticket snapshot with earlier answers.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Questions written | `WorkTracker.askQuestions`: one transaction, all or none. A run's question ids derive from the run (`<runId>-q<n>`) and `Question.runId` records it, so a replayed report finds them and writes nothing. Questions are written before the run is closed, so a crash between the two is finished by the replay.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Guards            | Refine starts only on a Backlog ticket with no open questions (answer first: the next pass sees the answers), at most 3 runs per ticket that reached the executor (ADR-0028). If the ticket left Backlog during the run, its questions are dropped and the run fails with the reason.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Auto-move         | The last answer on a Backlog ticket whose DoR is met moves it to Ready as `system`, through `TicketService.move` (re-reads, re-checks the DoR, writes with `ifUpdatedAt`). A conflict or unmet DoR leaves it in Backlog and is logged; the answer stands.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Size and tier     | The result also carries `size`, `sizeReason` and `tier`; they are written only where the ticket has none (Andy's values win). With them the Definition of Ready can be met from answers alone.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Who starts refine | The system: `RefineDispatcher` (`@andy/domain`) runs on events, never polls: after a ticket is created, after a ticket's last open question is answered while the DoR is still unmet (a new pass with the answers), and after each run ends, by report or by the watchdog (ADR-0055) (the next ticket's turn). It starts the oldest waiting Backlog ticket; one run per project in flight queues the rest. A reported failure follows ADR-0055 (one retry, then Needs-you). A rejected result, a failed dispatch or a 3rd pass that leaves the DoR unmet flags the ticket Needs-you with the reason and is not retried. Per-project `autoRefine` (default on; UI, `PATCH /api/projects/{p}`, MCP `set_auto_refine`) turns it off. Andy can still start refine himself (UI, REST, MCP `refine`). |

### Consequences

- Good: Andy only answers questions; tickets reach Ready without him starting anything. No free-text parsing; the agent can't write questions to another ticket or change a stage; replays can't duplicate; a broken result leaves no partial state.
- Bad: two copies of the limits (JSON schema for the agent, Zod for the check), held together by a test. Every new ticket spends subscription quota without Andy asking (capped: 3 refines per ticket, one run per project in flight, `autoRefine` off switch). A ticket with nothing to ask must still produce one question.
