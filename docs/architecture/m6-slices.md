# M6: Dev → prod releases — slices

Slice table for [milestones.md §M6](milestones.md#m6-dev--prod-releases). Epic: AI-153: M6: Dev → prod releases. Each ticket holds its acceptance criteria, out of scope and full `touches` (files it owns). **Risk** is the merge class from ADR-0092: medium = the coordinator may merge; high = Andy merges.

**Already built, not sliced:** safe deploy and rollback for the control plane (ADR-0076: `platform/actions/cloud-run-safe-deploy`, `deploy.yml`, runbook `deploy-and-rollback.md`); budgets, usage alerts and the opt-in kill switch for the control plane (`infra/billing`, `infra/control-plane`); `overrides.targetEnv` on tickets.

**Design in one paragraph** (recorded by M6.1 as ADR-0114, proposed): environments are a project setting, `prod-only` (default: one prod GCP project plus PR previews) or `dev-and-prod` (ADR-0050). Every deploy workflow reports a `Deployment` record to the control plane, so project AI feeds release notes, DORA and verification before any new GCP project exists. A merge moves the ticket to a new stage, Verifying (ADR-0069); the first environment deploys, a verify agent task checks it, and the verdict moves the ticket to Done or back. Promote and rollback dispatch a release workflow through the GitHub App; the API holds no Cloud Run credential.

## Questions for Andy

Full text with context in each ticket and the PR.

1. **Which tool should promote releases dev → prod: GitHub Actions with our safe-deploy action, or Google Cloud Deploy?** (M6.1) Actions reuses what deploys the control plane today, at no new cost; Cloud Deploy adds managed promote and approvals but one more service, IAM and a second deploy path. Recommendation: Actions (ADR-0114 records the deviation from ARCHITECTURE).
2. **Which app should be the first project on dev + prod, and will you create its two GCP projects by hand?** (M6.20) By hand: about 15 minutes per project, no standing grant; automatic creation needs Project Creator and Billing Account User. Recommendation: by hand, with AI-111: M5.4's project, named `<app>-dev` and `<app>-prod` (ARCHITECTURE open question 2).
3. **What default budget and caps should each managed project's environment get?** (M6.14) Options: $10/month, max 2 instances, kill switch off; the same with kill switch on; $5 and 1 instance. Recommendation: $10, 2 instances, kill switch on.
4. **Should the new stage be called Verifying, and should it apply to every project that deploys, including AI?** (M6.1, M6.5) Options: every project including AI; dev + prod projects only; "Released" (exit on prod). Recommendation: Verifying, every project including AI.
5. **Should prod uptime and error-rate alerts be part of M6?** (M6.19) One S slice, within Cloud Monitoring's free allowance; alert → ticket stays Later. Recommendation: yes.

**Milestone Done when** (ARCHITECTURE §12: per-project dev/prod deploys, verification, one-click promote, DORA metrics): M6.20's live proof on one project.
