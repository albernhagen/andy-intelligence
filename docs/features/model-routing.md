# Model routing

Which providers are on, each tier's routes (harness, provider, model) in order, and which tier each step uses: global, and per project (narrowing only). A save is refused with the reason when a route can't run (for example Jules on claude-sub) or a project config is wider than global, and each save is logged as a settings change (AI-239: M9.7). Agent tasks run on it: each dispatch reads global and the project's config and takes the first usable route with quota or spend room, recording each skip on the run (AI-238: M9.6, AI-261: M10.14). A `direct` route runs a single-call step in-process on OpenRouter, behind the spend caps (AI-258: M10.11); none is routed there by default. Each ticket's panel and MCP `status` show its build worker, tier and route, the layer that set each (ticket override, epic override, project default, global) and why earlier routes were skipped (AI-282: M9).

**How to use:** the ticket panel's Routing section; REST `GET /api/projects/<id>/tickets/<id>/routing`. Settings → Models (`/settings/models`): edit global or pick a project, reorder routes, see why a route would be skipped and the API's reason next to a refused one, and revert a global change from its Changes list (a project's from its settings Changes); MCP `get_routing`, `set_tier_routes`, `set_provider_routing`, `set_step_tier`, `list_routing_changes`, `revert_routing_change`; REST `GET`/`PUT /api/routing`, `PUT /api/projects/<id>/routing`
