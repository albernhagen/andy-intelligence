# Roadmap data

A project's milestones in order, each with its status (not reviewed, approved, parked), whether it is done (approved, with every epic Done), progress and open-ticket counts over its epics, and its epics' keys; epics with no milestone come under "No milestone" (AI-305, ADR-0131). Every top-level epic is listed too, in rank order, with its outcome, Done-when lines, state, progress and counts (needs you, in review, in progress, blocked, not started); child epics nest one level and count toward their parent (AI-193). Computed on read (cached board, one milestone list); never stored. The Roadmap screen shows it: one row per milestone, parked ones dimmed and done ones compact, each expanding to its epics, then No milestone (AI-202).

**Milestones** (ADR-0131, AI-304): a project's ordered groups of top-level epics, each not reviewed, approved or parked. Andy creates, renames, reorders and sets their status, and attaches an epic (its child epics and tickets take its milestone); each change is in the project's change log and can be reverted there. Creating, renaming and reordering are web only until AI-321: Milestone create and edit over MCP; milestones aren't deleted (park one).

**How to use:** milestones: MCP `list_milestones`, `set_milestone_status`, `set_epic_milestone`, or `GET`/`POST /api/projects/ai/milestones`, `PATCH …/milestones/:id`, `PUT …/tickets/:id/milestone`. Roadmap: header link Roadmap (`/p/<project>/roadmap`, `/all/roadmap`); drag a milestone's handle or use Move up and Move down to reorder (AI-324); MCP `roadmap`, optional `project`; `GET /api/projects/ai/roadmap`, or `GET /api/roadmap` for every project you can read (first 50 by key).
