# What's new

Release notes and project status on one page: per top-level epic, tickets done, in review, in progress and not started, and what needs Andy; then every PR merged into the default branch, newest first, by day, one line each ("What changed", ticket, PR), opening to "How it works", "Needs you" and the feature file, ADR and runbook it touched. A PR without a note shows its title, marked "No note" (ADR-0121). Status names the project's merge mode, and each change says who merged it: "merged by the mode (all-clean)" when the gate did, else the person (AI-218)

**How to use:** Header → What's new in a project (`/p/ai/whats-new`); filter by epic; waiting items and status sit beside the changes (first on a phone), with Open inbox (`G I`); window 24 hours, 14, 30 or 90 days (`?days=`). Yesterday's model-written summary leads (AI-323, [daily digest](daily-digest.md)), then the 24-hour digest's exceptions (waiting on Andy, blocked, reverted and the rest). The Digest screen is gone (AI-341); its URL opens the 24-hour view. MCP `whats_new` with `project`, optional `since`, `until`, `epic`; MCP `digest` unchanged. Every PR description carries the block (`release-note` check): `What changed:` (≤ 25 words), `How it works:` (≤ 45), optional `Needs you:` (≤ 25). Old PRs: [backfill runbook](../runbooks/whats-new-backfill.md)
