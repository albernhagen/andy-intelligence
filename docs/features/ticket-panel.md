# Ticket panel

A ticket slides in over the board, led by the decision (AI-336; direction A, AI-375). The header shows the status line, "PR #N waits for you" when a PR is open, and Close (Esc). **Next** is one row: the next move as the panel's one primary button, **Move…** (other allowed moves, Up next, Force move), **Open PR #N** and a Definition of Ready marker ("met" or "N missing", the missing items listed under it); then any open questions. The key sits above the title in mono. The rail beside the description is **Details** (type, size, epic, milestone, blocked by: Radix selects, no native select or checkbox anywhere in the panel), then **How it runs**, collapsed with its values in one line (worker, runs on, tier, model, override count): open it for the worker and runs-on option cards (the project-default lists plus "Use project default"), overrides and routing. Cancel and archive sit last. Each save shows a toast ("Saved Size on AI-1") with Undo. Activity is a timeline with a dot per event. An epic leads with its outcome, its breakdown (top-level only: Draft tickets, or the drafted tickets to approve or send back, [epic breakdown](epic-breakdown.md)), its tickets with progress, its milestone and Plan the night, then its description and lists. List fields with items (acceptance criteria or Done when, assumptions, out of scope, touches) show as before; empty ones fold into one **Add…** picker: pick one and type the first item (AI-330).

**How to use:** click a card on the board, or open `/p/<project>/t/<KEY>`; MCP `move_ticket`, `set_worker`, `set_executor` and `edit_ticket` do the same
