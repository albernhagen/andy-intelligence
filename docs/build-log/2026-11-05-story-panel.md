# 2026-11-05 — Story panel (AI-29)

AI-29: Story panel: the ticket as a side panel with a status line and markdown. Milestone M3: New UI and MCP; spec ADR-0059: UX foundation (rows "Story panel" and "Markdown").

- **Panel:** `/p/<key>/t/<KEY>` is now a child route of the board, rendered in the board's `<Outlet />`: a 640px panel on the right, full page under 900px. Esc (outside a field or editor) or Close goes back to `/p/<key>`. Direct loads show the board with the panel; old id URLs still switch to the key URL.
- **Status line:** `lib/status-line.ts`, one pure function over data the API already returns: stage, open questions, the run in flight (step, minutes since it started), the latest `pr_linked` event (number and open / merged / closed), unfinished blockers, place in the Ready lane. The API has no PR check state yet, so the line says "PR #61 open", not "checks running".
- **One document:** title, description, checklist ("Done when" for a chore), assumptions, out of scope, touches; a rail with stage and moves, Definition of Ready, type, size and reason, tier (from size unless pinned), epic, blocked by, cancel and archive; then questions (answerable in place) and one timeline of history, comments and runs (`timeline` in `lib/tickets.ts`; `run_linked` events are dropped since the run shows itself).
- **Edit in place:** each field saves only itself with `ifUpdatedAt`. Saves run one at a time per ticket and send the latest cached `updatedAt`, so two quick edits in different fields never conflict with each other. A 409 shows the API's message and a Reload button; the draft stays. Esc in an editor cancels it and leaves the panel open. Leaving the ticket with unsaved typing (Close, Esc, another card, a link, Back, a reload) asks first; the panel is keyed by ticket, so drafts never carry over to another one.
- **Markdown (trust-boundary change):** `react-markdown` 10.1.0 (exact). No `rehype-raw`, so HTML shows as text; `urlTransform` keeps only http, https and mailto; images never load (a link labelled with the alt text); links get `target="_blank"`, `rel="noopener noreferrer nofollow"` and their host. Used for descriptions, comments and question text; run summaries and other text stay plain. Threat model SPA line replaced.
- **Recomposed, not rewritten:** `TicketPage.tsx` is the panel; `History.tsx` became `Activity.tsx`; `Runs.tsx` exports `RunItem` and `StartRuns`; `MoveControls`, `CancelArchiveControls`, `QuestionCard` and `AskQuestionForm` are reused. `TicketForm` stays for creating tickets on the board.
- **Tests:** status line (every case), markdown (script, inline handler, `javascript:` link, raw HTML, remote image, URL allowlist), timeline order, and `panel.test.tsx` for every acceptance criterion against the in-process API. Screenshots: `story-panel.png` (reading, over the board), `story-panel-editing.png`, `story-panel-question.png`; `ticket.png` removed.
- **Open:** AI-29 has four open refine questions. Markdown library and images: ADR-0059 (approved 2026-11-04). Status-line data: what the API returns today, per the ticket. Unsaved edits: a confirm before they are lost (review of PR #80). On a phone the app shell's header is wider than the screen, which pushes the panel's Close button off-screen (the shell's fix, not the panel's).
