# 2026-11-21 — AI-238: M9.6: Route resolver

- Built `packages/domain/src/route-resolver.ts`. `effectiveRouting(global, project)`: a project only narrows global. A provider is on only if both have it on; the higher reserve and the lower warn, pause and daily task limit win; a project's tier keeps only routes global's tier has, in the project's order; a project may pick another tier for a step. `resolveRoute(step, ticketTier, routing, pin)` returns the first usable route (provider on, `routeProblem` null) and every route it skipped, with the reason.
- `RunService` reads the global and project configs once per start (refine, plan, build, sync) through the new optional `routing` dependency, wired to `FirestoreRoutingConfigStore` in `apps/api`. With nothing stored it uses `DEFAULT_ROUTING`, so every route is today's: all existing run and build tests pass unchanged.
- New behaviour: `overrides.modelPin` (it existed but nothing read it) now wins on `by_size` steps (plan, build, sync) when it is usable and is a route of some tier in the project's routing (a pin can't reach a model the routing leaves out); refine ignores it, as it ignores `overrides.tier`. A project's `steps` override global's (a project config holds every step). With no usable route the start is refused (`not_buildable` / `not_refinable`), the ticket gets one comment naming each skipped route, and it is flagged Needs-you.
- No quota-aware fallback (M10: Paid models + spend caps).
