# 2026-11-04 — Ticket model and UX foundation planned

- **Why:** Andy asked whether the system should support ticket types, priority, estimate and scope, and said the UI is not good enough: a project should feel like picking a tenant, moving a card to Done opens the ticket, status is hard to see. He wants Shortcut as the basis for an agentic system: markdown stories, simple swim lanes, never complicated.
- **ADR-0058: Ticket model.** Types become feature, chore and bug (plus epic) and each changes readiness, refine and build. No priority field: order in the column is the priority. Size S/M/L is the only estimate; tier is derived from it. New optional `outOfScope` and `touches`. A title alone is a valid ticket; refine drafts the rest and fills empty fields only. EARS for features = any "… shall" (settles a pending decision). Spikes noted for M2: Multi-project in parallel.
- **ADR-0059: UX foundation**, pulled forward from M5: Epics + story board (amends ADR-0045's timing): `design.md` and tokens, project switcher as a workspace picker, board cards that show status, the story as a side panel with safe markdown, command palette, screenshot checks. Dashboards and the design-skill trial stay in M5.
- **From Andy:** automatic is the default everywhere, with a way to step in at any point; drag order is enough for priority if the UI makes it clear; no spikes now; names are feature, chore, bug; ignore Jira and GitHub Issues.
