# 2026-11-04 — Dropping a card on the board opened the ticket (AI-25)

- Bug (AI-25: Dropping a card on the board opens the ticket): a mouse drop moved the ticket, then the browser loaded the ticket page in full.
- Cause: once a drag starts, dnd-kit adds a click listener on `document` (capture phase) that stops propagation, to swallow the click that ends a drag. React listens below `document`, so the card's `onClick` guard (the `justDragged` ref from AI-16: Board drag-and-drop) never ran. `stopPropagation` doesn't cancel the default action, so the browser followed the card link's `href`. The ref's timing was never the problem; the handler never ran.
- Reproduced in a real browser (Claude's browser pane) with a throwaway page: a dnd-kit draggable TanStack `Link`, the old guard, and a real mouse drag. The log showed `dragEnd`, then the click reaching `document` with `defaultPrevented=false`, no React `onClick`, and a full page load.
- Fix (`BoardPage.tsx`): `useDropClickSuppression` puts a capture-phase click listener on `window`, which runs before dnd-kit's. `onDragStart` arms it for mouse and touch drags (not keyboard drags, which end with Space and never click). The next click has its default cancelled, which also stops TanStack's `Link`. The flag is cleared by that click or the next `pointerdown`, not by a timer. A click with `detail === 0` (Enter on the link) is never cancelled, so keyboard activation still opens the ticket after a touch drop that left no click behind.
- Tests (`board.test.tsx`): mouse drop doesn't follow the link (committed failing first); click after a drop opens the ticket; Enter after a drop with no trailing click opens it; keyboard drop keeps the board. dnd-kit keeps swallowing clicks for 50 ms after a drop, so the tests wait 60 ms before clicking again.
- Checked in a real browser: drop keeps the board; a later click or Enter opens the ticket through the router. Not checked: touch drags on a real device, and the full app against the real API (local run needs Firebase sign-in).
