# 2026-11-05 — Build run: dispatcher, build step, PR (AI-3: M1.8a, first PR)

- **What:** a Ready ticket can now become a PR without Andy. `BuildDispatcher` takes the top Ready ticket by order (DoR met, blockers Done) on events only, in projects with `autoBuild` on (default off). The `build` run plans read-only, implements, runs the checks and returns plan, deviations and verification; a new `publish` job pushes `agent/<KEY>/<run>` and opens the PR `<KEY>: <title>` with the ticket link first. Decisions: ADR-0063.
- **Split:** AI-3: M1.8: Build + gate is three PRs: this one; `planApproval` (a read-only `plan` run approved before the build) next; then 8b (gate, auto-merge, metrics) as its own ticket.
- **Credentials:** the agent job still has no OIDC or write token. Bash runs only in Claude Code's sandbox (bubblewrap, registry-only network, credential variables unset, `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` for a PID namespace). The push token comes from `POST /github/token` through a new `TOKEN_POLICY` entry that gives one token per build run in flight.
- **Dispatcher rules (Andy, 2026-11-05):** never epics (milestone epics sit in Ready), never `overrides.assignee: "me"` (Andy's hands-on work; refine still runs), never archived or cancelled; an explicit start refuses the first two. Auto-build stays off: tickets whose work merged earlier still sit in Ready (AI-20, AI-24, AI-25, AI-26), so the first build on project `AI` is Andy's explicit start.
- **Found on the way:** the PR review jobs run the PR's own `platform/actions/agent-review-*` and `scripts/review-*.mjs` while holding the Claude token (R5). Agent PRs may now be written without Andy, so those paths, and all of `.github/`, are Edit-denied and refused by the publish job. The catch-all CODEOWNERS `*` line no longer becomes an Edit deny (it would have denied every edit).
- **Not proven live yet:** the sandbox keys and the env scrub on Actions runners. Runbook `agent-runs.md` §9 has the probe (AI-12's deferred counted denial).
- **Tests:** a flow test drives the real API in-process: auto-build on → ticket to Ready → build dispatched on Opus (size M) → ticket In progress → context → one push token (a second refused) → report with PR → PR webhook → Ready for review. Plus dispatcher order, blockers, caps, retry with kept branch, foreign PR/branch rejection, profile and publish-check tests.
- **Also:** `ProjectPatch` is declared without defaults: with Zod's `.partial()`, patching one switch reset the other to its default.
- **Review answers (PR #83):** security high: `infra/` and `.terraform-version` are now refused (`terraform-plan` runs them with GCP credentials), with `.mcp.json`; package scripts and test config stay writable because only secret-free jobs run them (threat model R2). A change over the 5 MB cap or one git can't collect now fails the run with the reason instead of reading as "no change".

## Next PR: `planApproval` (AI-3, 8a part 2)

For a fresh session: branch from `main` after PR #83 merges. ADR-0063 holds the build protocol; this PR adds the approval step.

- **Contracts:** `Project.planApproval`: `none | m-and-l | all`, default `none`, in `ProjectPatch` (declared without defaults; keep it so). A plan decision (approved or rejected, reason, by, at) on the plan Run.
- **Domain:** when the policy applies to the ticket's size, dispatch (and an explicit build start) first runs a read-only `plan` step: add it to `STARTABLE_STEPS` and `STEP_LIMITS`; `profile.json` `steps.plan` is already read-only; add `platform/procedures/plan.md` and `plan.schema.json` (reuse `BuildPlan`). Its report stores the plan, flags the ticket Needs-you and starts nothing. Approve → the build run starts with the approved plan in its prompt (the build procedure follows it and records deviations). Reject with a reason → comment, flag; the next plan run sees the reason. The dispatcher must skip a ticket whose plan awaits a decision.
- **API, UI, MCP:** approve and reject with a reason (REST under the ticket; buttons in the Runs panel; MCP `approve_plan`, `reject_plan`), a `planApproval` select on `/projects` and its MCP setter.
- **Tests:** GivenX_WhenY_ThenZ; extend `apps/api/src/build-flow.test.ts` with policy `all`: plan run → flagged → approve → build → PR.
- **Docs:** a new ADR only if the design differs from ADR-0050/0063; otherwise `workflow.md` §4.1 built note, `executors.md`, `api-and-mcp.md`, the §8.1 build row, runbook `agent-runs.md` §8, the threat model (approve is Andy-only), a build-log entry.
