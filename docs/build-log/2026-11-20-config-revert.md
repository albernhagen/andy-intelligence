# 2026-11-20 — AI-119: M4.12: Config audit log and revert in UI and MCP

- Revert lives in `ConfigRevert` (`packages/domain/src/config-revert.ts`): owner-only through the existing `change_project_settings` action (no change to `permissions.ts`); the before values go through `ProjectService.update`, so the revert is logged as a new change with reason `Revert of <id>`, then the original is marked `reverted` (new `ConfigChangeLog.markReverted`, transactional on Firestore; `decidedBy`/`decidedAt` record who and when).
- Refused (409 `not_revertible`) when a newer logged change touched one of its fields (named in the error; a change in the same millisecond counts as newer), or a field no longer holds the change's after value. So a second revert of the same change is refused too.
- MCP tool names differ from the ticket: `list_config_changes` already lists pending proposals (ADR-0097), so the log tools are `list_settings_changes` and `revert_settings_change`. Over MCP a change that switches Builds can't be reverted: Builds is set only in the app (ADR-0063).
- Docs are terse because `api-and-mcp.md`, `domain-and-ports.md`, `docs/security/ui-and-mcp.md`, the threat model and `README.md` were at their word budgets: the revert joins the owner-only line in `ui-and-mcp.md` instead of a line of its own.
