## What changed, in plain words

- **"Run" is now "agent task"** everywhere Andy reads it: UI, MCP descriptions, messages, docs (AI-43).
- **The local executor exists up to read-only tasks.** A project or ticket can be set to `local`; Andy can mint and revoke runners; a runner on his Mac polls, claims refine and plan tasks, runs them sandboxed and reports (AI-79, AI-131; ADR-0089, ADR-0094, ADR-0098). Nothing has run live yet. Local builds are PR #182.
- **Epics are usable.** The board groups by epic, an epic's panel shows its children with roll-ups and cost, and an epic's overrides cascade to its stories (AI-85, AI-86, AI-116).
- **A plan is redone when a blocker lands** after it was written (AI-88).
- **Each agent task has its own page** with model, status, cost, gate verdict, plan and checks (AI-101), and there is a data API for dashboards (AI-102).
- **Night launches have a model and a readiness check**, no dispatch yet (AI-104).
- **Several projects:** `list_projects` over MCP, ticket lookup by key and stage counts without reading whole projects, fair dispatch across projects when a global slot frees, blockers across projects, a setup checklist on the project page (AI-89, AI-90, AI-91, AI-96, AI-95).
- **Repeated review findings can become one pending config change** for Andy to accept or dismiss; it never applies anything itself and has no data until findings are stored, which is PR #186 (AI-100).
- **Small fixes:** an MCP tool accepts a held refine gap (AI-132); `create_ticket` resolves a parent given as a key (AI-130); the executor tests no longer run git in the developer's repository (AI-135); `docs/features.md` tightened from 1499 to 1250 words (#188).
- **M4 and M5 are sliced** into 23 tickets each (AI-80, AI-81).
