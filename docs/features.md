# Features

Living catalog of what is shipped on `main`, one row per feature; update it in the same PR as a feature change (ADR-0022). Summary: `README.md` "How it works today". Target design: [ARCHITECTURE.md](architecture/ARCHITECTURE.md).

**Working:**

| Feature                | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | How to use                                                                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sign-in                | Google sign-in; only emails on the allow-list get in                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Open `https://ai.andybernhagen.com` ([custom domain runbook](runbooks/custom-domain.md))                                                                             |
| Tickets                | Projects, tickets moving through stages (Backlog → … → Done, or Cancelled) by drag-and-drop or buttons; a title alone is a ticket; type sets the Definition of Ready; tier comes from size; a ticket opens over the board: status line, markdown, in-place edits, one timeline; Andy can force any move; archive hides finished ones                                                                                                                                                                                                                                                                                            | UI: pick the project at the top left, then Board; or the REST API under `/api`                                                                                       |
| Tickets follow PRs     | A PR on a project repo whose branch or description's first line names a ticket (`AI-14`, or its link) moves it from any open stage: opened into the default branch → Ready for review, merged into it → Done, closed unmerged → In progress + Needs-you; fork PRs, drafts and epics don't move                                                                                                                                                                                                                                                                                                                                  | Name the ticket in the branch or start the PR description with its link ([runbook](runbooks/mcp-connector.md) §4c)                                                   |
| Needs-you inbox        | One card per ticket, most unblocking first; one-click answers                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | UI home `/`: the inbox in the last-picked project, or All projects                                                                                                   |
| GitHub App + webhooks  | Connect GitHub once from the UI (two clicks on GitHub); PR, check and workflow events on registered repos are then recorded once each (replays are no-ops)                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | UI: Settings → Connect, then Install on repos ([runbook](runbooks/github-app.md))                                                                                    |
| Project registration   | A project's repo must have the GitHub App installed and belongs to one project; project #1 is this repo (`AI`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | UI `/projects` → "GitHub repo" (suggests installed repos)                                                                                                            |
| Claude connector (MCP) | Claude desktop signs in through our OAuth server; tools to create, refine, build, answer, move (one step forward), cancel and archive tickets, approve or reject plans, `status`, and project switches; same rules as the UI                                                                                                                                                                                                                                                                                                                                                                                                    | [`docs/runbooks/mcp-connector.md`](runbooks/mcp-connector.md)                                                                                                        |
| Agent runs             | Claude Code on GitHub Actions under a locked-down permission profile, on Andy's subscription; one run per project. Refine (read-only) starts on its own for each new Backlog ticket, fills empty fields, comments a report and asks 1–5 questions in Needs you; the last answer moves the ticket to Ready, or starts another pass. **Build** (off by default) takes the top Ready ticket: plans, implements, checks in a sandbox, opens a PR `<KEY>: <title>` with plan and verification; with plan approval, Andy approves a read-only plan first. A watchdog checks unreported runs; failures retry once, then flag Needs-you | "Auto-refine", "Builds", "Auto-build", "Plan approval" on `/projects`, or MCP; by hand: ticket → Runs, or MCP `refine` / `build` ([runbook](runbooks/agent-runs.md)) |
| PR checks              | Lint, typecheck, tests, build, secret/CodeQL/dependency/Terraform scans, security-review and adversarial-review agents; weekly system review PRs are opened with a control-plane App token, so their checks run                                                                                                                                                                                                                                                                                                                                                                                                                 | Automatic on every PR; overrides with the `security-accepted` / `review-accepted` labels                                                                             |
| Dependabot updates     | Weekly grouped PRs; npm patches (and minors of 1.0+ packages) auto-merge after the checks pass and deploy with Andy's next merge; majors, 0.x minors, Actions and Terraform wait for Andy, who is requested as reviewer (CODEOWNERS)                                                                                                                                                                                                                                                                                                                                                                                            | Nothing for auto-merged ones; review the rest                                                                                                                        |
| Project baseline       | Gives another repo the same checks, files and GitHub settings                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | `platform/baseline/baseline.mjs` ([runbook](runbooks/onboard-a-repo.md))                                                                                             |
| Cost guardrails        | $25/month budget alerts, usage alerts, caps, opt-in kill switch at 150% of budget                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | [`docs/runbooks/billing.md`](runbooks/billing.md)                                                                                                                    |
