| Claude connector (MCP) | Claude desktop signs in through our OAuth server; tools to create (Ideas unless `upNext`), refine, build, answer, promote an assumption, move (one step forward), edit, comment on, re-parent and reorder, cancel and archive tickets, approve or reject plans, `status` (with the UI's status line), `list_ready` (Ready tickets with scores, filter by size, risk, confidence), and project switches; same rules as the UI                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | [`docs/runbooks/mcp-connector.md`](runbooks/mcp-connector.md)                                                                                                                                                                          |
| Agent runs             | Claude Code on GitHub Actions under a locked-down permission profile, on Andy's subscription; runs at once per project on a dial (default 2, max 4), under a global cap (4), a cap on agent PRs waiting (5), a pause switch and the quota reserve; the page and MCP `status` say why dispatch is idle (ADR-0079). A Ready ticket whose `touches` overlap a build in flight waits while the next one starts; the board's In flight panel and MCP `list_in_flight` list runs in flight with their files, and each build gets a reserved ADR number (ADR-0080). Refine (read-only) starts on its own when a ticket enters Up next (Ideas never run it), fills empty fields (including risk and confidence, each with a reason) and comments a report, or sends it back to Ideas with a reason, or splits it into at most 5 Ideas. It asks only when a guess would be unsure or costly to reverse (3 open per ticket, `dailyQuestionCap` a day); the rest become assumptions on the ticket, and "Ask me instead" turns one into a question. With nothing to ask and the Definition of Ready met, it goes straight to Ready; the last answer also does, or starts another pass. **Build** (off by default) takes the top Ready ticket: plans, implements, checks in a sandbox, opens a PR `<KEY>: <title>` with plan and verification; with plan approval, Andy approves a read-only plan first. A watchdog checks unreported runs; failures retry once, then flag Needs-you | "Auto-refine", "Builds", "Auto-build", "Runs at once", "Paused", "Plan approval" in Project settings, or MCP (`set_runs_at_once`, `set_paused`); by hand: ticket → Runs, or MCP `refine` / `build` ([runbook](runbooks/agent-runs.md)) |
